# AI-001 / AI-002 / AI-003 - Retired per-provider web access rules

> **Detection IDs:** AI-001, AI-002, AI-003 (retired runbook IDs; no package ships them)
> **Status:** Retired. Replaced by [AI-028](AI-028.md), package `hdsi_ai_unsanctioned_web_access`, search `Network - HDSI AI Unsanctioned Web Access - Rule`
> **Last Updated:** 2026-10-09

---

## What happened to these rules

AI-001, AI-002 and AI-003 were three separate web-access rules, one each for ChatGPT, Claude and Gemini. They were folded into one rule before 1.0.0, and the 1.1.0 release ships no saved search for them. There is nothing to deploy, enable or disable.

One rule per provider did not scale. Each new provider needed a new stanza, the three searches were identical apart from the domain, and a user who visited two providers collected double risk for the same behaviour.

## Where the coverage lives now

| Need | Use |
|---|---|
| Unsanctioned use of any AI web app (ChatGPT, Claude, Gemini and every other provider in `ai_provider_domains` / `ai_provider_apps`) | [AI-028](AI-028.md): `Network - HDSI AI Unsanctioned Web Access - Rule` (package `hdsi_ai_unsanctioned_web_access`). Risk on the user, dynamic 3-30, one event per user and provider per day |
| The same providers seen in DNS, from hosts | [AI-012](AI-012.md): `Network - HDSI AI DNS Queries To AI Domains - Rule` |
| A user's first visit to a provider | [AI-009](AI-009.md): `Network - HDSI AI First Seen Provider For User - Rule` |

To handle one provider differently, use the `provider` field. Approve it in `ai_sanctioned_entities` (common package `hdsi_ai_rba_common`) or `hdsi_ai_unsanctioned_web_access_sanctioned_providers`, or filter it in `hdsi_ai_unsanctioned_web_access_customizations`. Do not recreate a per-provider rule.
