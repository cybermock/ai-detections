# AI-014 - Local LLM Listening Port Detected

> **Detection ID:** AI-014
> **Package:** `hdsi_ai_local_llm_listening_port_detected` (v1.1.0, deployment type `global`, ships `enable_alerting: false`)
> **Search name:** `Network - HDSI AI Local LLM Listening Port Detected - Rule` (the `Network` prefix is kept so existing deployments update in place; `security_domain` is `endpoint`)
> **Status:** Active (risk-only: `action.risk = 1`, `action.notable = 0`)
> **Risk Score:** `dest` (system) only: 50 when any listener on the host is reachable from the network, otherwise 30 (loopback-only or bind address not reported). Literal `_risk` fallback 30
> **MITRE ATT&CK:** T1588.007 - Obtain Capabilities: Artificial Intelligence (Resource Development)
> **Data Model:** `Endpoint.Ports` AND `Endpoint.Processes`
> **Schedule:** `27 * * * *` (hourly at minute 27)
> **Lookback Window:** `-65m@m` to `-5m@m` for listeners; process attribution looks back `-7d@h`
> **Suppression:** 24 hours (`86400s`) on `dest`
> **Kill Chain Phase:** `staging` (multi-vector aggregator vector: `local_tooling`)
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds a local LLM server listening for API requests on a host: Ollama (11434), LM Studio (1234), Jan (1337), GPT4All (4891, including Windows `chat.exe`), and KoboldCpp, llama.cpp server, LocalAI or vLLM on 5001/8000/8080 when the process is reported under its own name. Each listener must be attributed to its owning Local LLM process from `Endpoint.Processes`; port-only matches are not trusted.

A local model server runs AI outside every sanctioned SaaS control. Ollama and most of the others serve an **unauthenticated** HTTP API. A server bound to `0.0.0.0` instead of loopback lets anyone on the network use the model, pull or delete models, or exploit server bugs (for example CVE-2024-37032, an Ollama path traversal). The rule writes risk on the host (`dest`, system) only, and creates no notable. AI-011 covers process execution; this rule adds proof that the tool is serving, and how widely it is exposed.

Typical actors: developers running Ollama or LM Studio's server for local tools and IDE plug-ins; shadow GPU servers shared with a team; less often, an exposed server that outsiders can abuse.

## Detection Logic

### Plain English

1. `tstats` over `Endpoint.Ports` keeps TCP listeners on the dedicated ports (`_ports`: 11434, 1234, 1337, 4891) and generic ports (`_generic_ports`: 5001, 8000, 8080), excluding connection states (`established`, `time-wait`, ...). It groups by `host`, bind address and port with `values(process_id)`.
2. An appended `tstats` over `Endpoint.Processes` looks back 7 days for processes in `_process_names`, resolves them through `ai_process_filter` and keeps `provider="Local LLM"` (excluding `lms`/`lms.exe`, which collide with Intel LMS).
3. Hosts are normalised to a lowercase short name; hex PIDs (Windows 4688) and decimal PIDs are normalised.
4. Attribution:
   - **PID:** the listener's own `process_id` belongs to a Local LLM process on that host. The only path for generic ports.
   - **Host:** no source reports any PID for that host and port (netstat-only), the port is dedicated, and a Local LLM process ran on that host in the lookback. A listener whose PID is known but is not an LLM process is always dropped. `chat.exe` counts by PID only.
5. `_corroboration` drops listeners with no `llm_process`.
6. `exposure`: `loopback` for `127.*`/`::1`/`::ffff:127.*`; `unknown` when no bind address is reported; anything else (`0.0.0.0`, `*`, `::`, an interface IP or the host name) is `network`.
7. Aggregate per host, remove sanctioned entities (`ai_unsanctioned_filter(user,dest,provider)`), and score 50 (network) or 30.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `dest` | Host running the server (only risk object, suppression key) | `ws-0142` |
| `llm_tool` / `llm_process` | Tool and owning process name(s) | `ollama` / `ollama.exe` |
| `ports` | Listening port(s) | `11434` |
| `bind_addrs` | Bind address(es) | `0.0.0.0` |
| `exposure`, `exposure_label`, `network_exposed` | Exposure class, readable label, 1 if network-reachable | `network`, `reachable from the network`, `1` |
| `attribution` | `process_id` or `host` | `process_id` |
| `user` | First non-service account that ran the process (context only, not a risk object) | `jdoe` |
| `listen_events`, `port_sourcetype` | Listener events and their sources | `2`, `XmlWinEventLog:Security` |
| `risk_score` | 50 or 30 | `50` |
| `detection_id`, `ai_activity`, `ai_kill_chain_phase` | Constant tags | `hdsi_ai_local_llm_listening_port_detected`, `local_llm_server_listening`, `staging` |

### Thresholds

None. Any attributed listener counts. One risk event per host per day (24 h suppression on `dest`).

## Triage Steps

> **Estimated triage time:** 10-20 minutes. Replace `$dest$` with the host from the risk event and `$pid$` with the listener PID from Step 2. Set the time picker to the last 24 hours for risk queries.

### Step 1: Read the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Network - HDSI AI Local LLM Listening Port Detected - Rule" risk_object="$dest$"
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- The message gives the tool, owning process, ports, exposure label and bind addresses. Score 50 = reachable from the network.

### Step 2: Review the listeners on the host

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime values(Ports.process_id) as process_id values(sourcetype) as sourcetype
    from datamodel=Endpoint.Ports
    where (host="$dest$" OR host="$dest$.*") Ports.dest_port IN (`hdsi_ai_local_llm_listening_port_detected_ports`,`hdsi_ai_local_llm_listening_port_detected_generic_ports`) earliest=-24h
    by host Ports.dest Ports.dest_port Ports.transport Ports.state
| rename Ports.dest as bind_addr, Ports.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - lastTime
```

- `bind_addr` of `0.0.0.0`, `*`, `::`, an interface IP or the host name = network-reachable. Windows Filtering Platform events (5154 listen, 5158 bind) report non-loopback binds as the host name.
- Note the `process_id` for Step 3.

### Step 3: Confirm the owning process

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime values(Processes.process) as process values(Processes.process_path) as process_path values(Processes.parent_process_name) as parent_process_name
    from datamodel=Endpoint.Processes
    where (Processes.dest="$dest$" OR Processes.dest="$dest$.*") earliest=-7d@h Processes.process_name IN (`hdsi_ai_local_llm_listening_port_detected_process_names`)
    by Processes.dest Processes.user Processes.process_name Processes.process_id
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - lastTime
```

- With `attribution=process_id`, the listener PID matches one of these rows (Windows 4688 logs hex PIDs such as `0x1a2b`; 5154 and Sysmon log decimal).
- With `attribution=host` (netstat-only listener), confirm on the host that the port belongs to the LLM server, for example `netstat -ano | findstr :11434` (Windows) or `ss -ltnp 'sport = :11434'` (Linux), through EDR live response.
- Command line or environment showing `OLLAMA_HOST=0.0.0.0`, `--host 0.0.0.0` or LM Studio "serve on local network" explains a network bind.

### Step 4: Check whether other hosts connected to the server

```spl
| tstats summariesonly=t allow_old_summaries=t count dc(All_Traffic.src) as clients values(All_Traffic.src) as src values(All_Traffic.action) as action
    from datamodel=Network_Traffic
    where All_Traffic.dest="$dest_ip$" All_Traffic.dest_port IN (11434,1234,1337,4891,5001,8000,8080) earliest=-7d
    by All_Traffic.dest All_Traffic.dest_port
| rename All_Traffic.* as *
```

- Replace `$dest_ip$` with the host's IP address (`asset_lookup_by_str`). Always scope to the host: on Tenant A the firewall logged about 500,000 events a day on port 11434 from 1,440 sources, mostly ephemeral-port collisions and scanning.
- Allowed connections from other internal hosts mean the server is in shared use. Connections from outside the internal network on a network-bound server are a security incident.

### Step 5: Correlate with execution, downloads and other AI risk

```spl
| from datamodel:"Risk.All_Risk"
| search (risk_object="$dest$" OR risk_object="$user$") source="* - HDSI AI * - Rule"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources values(ai_kill_chain_phase) as phases by risk_object risk_object_type
| sort - total_risk
```

- Expect AI-011 (execution) on the same host; AI-013 (model download) shows where the model came from. `$user$` is the `user` context field from the risk event.

### Step 6: Identify the owner and check sanctioned status

```spl
| inputlookup asset_lookup_by_str
| search dns="$dest$*" OR nt_host="$dest$"
| table ip dns nt_host owner bunit category priority
```

```spl
| inputlookup ai_sanctioned_entities
| where enabled=1 AND (lower(entity)=lower("$dest$") OR lower(entity)=lower("$user$") OR entity="*" OR entity_type="group") AND (provider="*" OR lower(provider)="local llm")
| table entity_type entity provider scope expires owner reason allow_key
```

### Step 7: Make a determination

- **True Positive:** an unapproved local LLM server, especially network-reachable or with connections from other hosts.
- **Benign True Positive:** an approved AI workstation or GPU server. Allow-list it with an expiry.
- **False Positive:** the listener belongs to a different product on the same port (host attribution on a netstat-only host). Tune it.

---

## True Positive Indicators

- `exposure=network` (score 50) on a workstation, or allowed inbound connections from other hosts in Step 4.
- Owning process confirmed by PID as Ollama, LM Studio, llama-server, KoboldCpp, LocalAI or GPT4All.
- Recent model downloads (AI-013) and execution (AI-011) on the same host; the host handles sensitive data.
- An Ollama version vulnerable to known API flaws on a network-bound listener.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Other products on the same ports: a micro-segmentation agent on loopback 11434/1337/4891, an OCR imaging service on `127.0.0.1:11434`, middleware on `*:1234`, web apps on 5001/8000/8080 (14 hosts on Tenant A and 46 on Tenant C would have fired port-only) | High if corroboration is removed | PID attribution drops them. Do not remove `_corroboration` tenant-wide |
| Host attribution on a netstat-only host that also ran an LLM runtime: a non-LLM listener on a dedicated port is credited to the runtime | Low | Generic ports always need a PID; confirm the port owner on the host (Step 3) and exclude the host in `_filter` if needed |
| Sanctioned AI workstations and GPU servers | Medium | Add `<host>|local llm` (or `<host>|*`) to `ai_sanctioned_entities` |

## Response Actions

### If confirmed True Positive

1. **Contain:** for a network-reachable server, rebind to loopback (`OLLAMA_HOST=127.0.0.1`, disable LM Studio "serve on local network") or block the port on the host firewall immediately. Stop the service if policy forbids local LLMs.
2. **Notify:** the host owner's manager and the AI governance owner; incident response if outside or unexpected internal clients connected.
3. **Investigate:** list connecting clients (Step 4), loaded models, and the server version against known vulnerabilities. Check for models pushed or deleted through the API.
4. **Remediate:** uninstall or update the runtime, enforce application control, or move the use case to a sanctioned platform.
5. **Document:** record tool, ports, exposure, clients and disposition.

### If Benign True Positive

1. Add the host to `ai_sanctioned_entities` with an `expires` date, for example:
   ```
   entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
   system,ml-gpu-07,Local LLM,provider,2027-03-31,<owner>,<approved GPU server, loopback only>,1,ml-gpu-07|local llm
   ```
2. Approve loopback-only configurations by default; require a documented exception for network-bound servers.

## Tuning Guidance

### Reducing false positives

- Keep `_corroboration` as `where isnotnull(llm_process)`. Relax it only for hosts with no process telemetry, for example `where isnotnull(llm_process) OR (dest_port="11434" AND NOT match(bind_addr,"^127\."))`.
- Exclude approved hosts with `hdsi_ai_local_llm_listening_port_detected_filter` (inside the `Endpoint.Ports` where clause, for example `NOT host IN ("lab-gpu-*")`), or better, with the sanctioned-entities lookup.
- Add a custom port to `_ports` only if users commonly move Ollama off 11434 (`OLLAMA_HOST=0.0.0.0:9999`).
- Override the score at the last pipe (`hdsi_ai_local_llm_listening_port_detected_risk_score`), for example raise network-exposed servers in a DMZ. Keep it at or below 100.

### Reviewing what listens on the configured ports

Run this over 7 days before enablement (the rule with the corroboration gate opened), then resolve one host per port to its owning process with Steps 2-3:

```spl
| tstats summariesonly=t allow_old_summaries=t count dc(host) as hosts values(Ports.dest) as bind_addr
    from datamodel=Endpoint.Ports
    where Ports.dest_port IN (`hdsi_ai_local_llm_listening_port_detected_ports`,`hdsi_ai_local_llm_listening_port_detected_generic_ports`)
      Ports.transport IN ("tcp","tcp6")
      NOT Ports.state IN ("established","time-wait","close-wait","syn-sent","syn-recv","fin-wait-1","fin-wait-2","last-ack","closing")
      earliest=-7d
    by Ports.dest_port sourcetype
| sort - hosts
```

### Known blind spots

Servers started before the 7-day process lookback and seen only by netstat; custom ports; interpreter-launched servers (text-generation-webui, vLLM or Open WebUI reported as `python`); containers (`com.docker.backend`, `wslrelay`, `vpnkit` own the socket); macOS and Linux laptops that send no `Endpoint.Ports`; LM Studio's `lms` CLI (excluded because of Intel LMS; LM Studio is still matched through `LM Studio.exe`/`lmstudio`).

## Data Requirements

| Requirement | Details |
|---|---|
| Data Model | `Endpoint.Ports` AND `Endpoint.Processes`, both accelerated (`summariesonly=t`) |
| Required Fields | Ports: `dest_port`, `transport`, `state`, `dest` (bind address), `process_id` (for PID attribution), `host`. Processes: `dest`, `process_id`, `process_name`; `user` optional |
| Sourcetype Examples | Windows Security 5154 (listen) and 5158 (bind) via "Audit Filtering Platform Connection"; Splunk Add-on for Unix and Linux `netstat` (no PID); scripted listening-port inventories with PID; Windows 4688 / Sysmon for processes |
| Not useful | `Network_Traffic` (firewalls do not see loopback; used by v1.0, which could never fire); Windows Security events mapped with `dest_port=0` and no state (Tenant D) |
| CIM Compliance | `Ports.dest` must be the bind address, `state` must distinguish listening from connection states |
| Acceleration | Required for both |
| Lookups | Common package `hdsi_ai_rba_common`: `ai_tool_processes` (via `ai_process_filter`, `provider="Local LLM"`), `ai_sanctioned_entities` (via `ai_unsanctioned_filter(3)`). No ES identity or asset lookups |
