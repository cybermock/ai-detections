# AI-035 - HDSI AI Assisted Lateral Movement

> **Detection ID:** AI-035
> **Package:** `hdsi_ai_assisted_lateral_movement` (v1.1.0, `deployment_type: global`, requires `hdsi_ai_rba_common`)
> **Search name:** `Threat - HDSI AI Assisted Lateral Movement - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`, `action.risk = 1`); the HDSI RBA AI aggregators decide when accumulated risk becomes a notable.
> **Risk Objects / Score:** `user` (user) 50 and `src` (system, the host where the agent ran) 40, static. Non-personal accounts (`unknown`, Codex sandbox accounts) give host risk only.

> **Schedule:** `2-59/5 * * * *` (every 5 minutes)
> **Lookback Window:** `-15m@m` to `-5m@m`

> **Kill Chain Phase:** `lateral_movement` (`ai_kill_chain_phase`)

## Overview

This detection fires when an **AI coding agent launches a remote-access or remote-execution command**. Covered agents include Claude Code (npm and native installs), Codex (including its Windows command runner), Gemini CLI, Google Antigravity agent terminals, GitHub Copilot CLI and the Copilot agent runtime in VS Code, Aider, Amazon Q, OpenCode and similar tools. Covered commands include SSH, PsExec, WinRM/PowerShell remoting, RDP, `wmic /node:`, `net use \\host`, admin-share paths (`\\host\c$`, `\\host\admin$`), cloud remote shells, and offensive frameworks such as Impacket and NetExec.

An agent runs with the developer's credentials and can reach whatever that developer can reach. A prompt injection (from a web page, an issue, a README or an MCP tool result) or plain misuse can turn the agent into a pivot point, and its commands run without a human typing them. The link is causal: the remote command is a direct child of the agent (usually the shell the agent spawned), not a time-window coincidence.

Expected volume is near zero today. Treat every hit as worth a look; sanctioned DevOps use should be allowlisted once rather than triaged repeatedly.

## Detection Logic

### Plain English

1. **One `tstats` over `Endpoint.Processes`** keeps processes whose **parent** is an AI coding agent (`..._agent_parents`): a native agent binary, a versioned command runner (`codex-command-runner-<ver>.exe`, `copilot-runtime.exe`, `copilot-language-server.exe`), a `node`/`bun`/`python` host whose command line names the agent, the Claude Code native installer (matched on the parent command line, because some EDRs log the parent name as the version string), or a Google Antigravity agent shell.
2. **Benign fragments are stripped** from each lowercased child command line (`..._benign_regex`): git transport over SSH, `ssh -T git@github.com` style auth tests to public code hosts, ssh to localhost, version, help and query-only invocations, quoted git/gh commit and PR messages, cat/tee heredoc bodies, and local `-ComputerName .`, `/node:localhost`, `\\localhost`. Only the fragment is removed, so a real hop elsewhere in the same line is still caught.
3. **The remainder is matched against `..._remote_regex`.** Remote clients must be in command position (start of line, after `; & | ( {`, a shell `-c`, `do`/`then`, or a wrapper such as `sudo`, `xargs`, `env`, `timeout`), so `which ssh` or `grep -c ssh` do not match. `scp`/`rsync` need `host:`; `net use`, `sc`, `reg` need `\\host`; PowerShell remoting needs `-ComputerName`; admin-share paths and offensive tools match anywhere.
4. **Derived fields:** `remote_method`, best-effort `remote_targets`, `remote_commands` (first 5, 300 characters each, with common credential forms replaced by `<redacted>`), and `offensive_tooling`.
5. **Provider and tool** come from the common `ai_tool_processes` lookup (by parent name, then by the tool derived from the parent command line).
6. **Allowlist per agent row:** `ai_unsanctioned_filter(user,src,provider)` drops sanctioned users, hosts, business units and organisation-wide entries before aggregation.
7. **Aggregate per `user` and `src`.** Placeholder and Codex sandbox accounts get no user risk object.
8. **Score:** literal user 50, system 40; `risk_score=70` only with offensive tooling.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `src` | Host where the agent ran (system risk object) | `DEV-WS-0142` |
| `user` / `actor` | Account the agent ran as; `actor` reads "an unidentified account" when null | `jdoe@example.com` |
| `ai_tools` / `agent_processes` | Agent tool names and parent process names | `claude` / `claude.exe` |
| `provider` | Agent provider (allowlist key part) | `Anthropic` |
| `remote_methods` | ssh, smb, winrm, rdp, wmi, cloud_shell, other | `ssh` |
| `remote_targets` | Parsed target hosts (max 10), or "not parsed" | `db01.example.com` |
| `remote_commands` | First 5 matching command lines, credentials redacted | `bash -lc ssh admin@db01 'systemctl restart app'` |
| `child_processes` | Processes the agent launched | `bash` |
| `offensive_tooling` | 1 for Impacket, NetExec/CrackMapExec, evil-winrm | `0` |
| `bunit` | Identity business unit | `platform engineering` |

### Thresholds

The rule has no numeric threshold. Every agent-launched remote command counts.

| Parameter | Default Value | Macro | Notes |
|---|---|---|---|
| User score | 50 | `_risk` literal | Static, no multiplier |
| System score | 40 | `_risk` literal | Static |
| Offensive tooling score | 70 (both objects) | in SPL; override in `hdsi_ai_assisted_lateral_movement_risk_score` | Keep at or below 100 |

## Triage Steps

> **Estimated triage time:** 15-30 minutes. There is no notable for this rule. You reach it from an HDSI RBA AI aggregator notable or a risk event. Set the time picker to cover at least an hour before the risk event.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Threat - HDSI AI Assisted Lateral Movement - Rule" risk_object IN ("$user$","$src$")
| table _time, risk_object, risk_object_type, risk_score, risk_message
| sort - _time
```

- The risk message names the agent, the host, the methods, the account and the targets.
- A score of 70 means offensive tooling. Escalate immediately (go to Response Actions while you continue triage).

### Step 2: Review everything the agent launched on the host

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime values(Processes.process) as process
    from datamodel=Endpoint.Processes
    where Processes.dest="$src$" `hdsi_ai_assisted_lateral_movement_agent_parents`
    by Processes.user Processes.parent_process_name Processes.process_name
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

- Read the commands in order. Was the agent building or deploying code that legitimately needs a server, or did it start doing reconnaissance (`whoami`, `net group`, `nltest`, credential file reads) before the remote command?
- Look for downloads (`curl`, `iwr`) or encoded commands around the remote command.

### Step 3: Confirm whether the remote command reached the target

Replace `$remote_target$` with a host from `remote_targets`:

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime
    from datamodel=Authentication
    where (Authentication.dest="$remote_target$*" OR Authentication.src="$src$")
    by Authentication.src Authentication.dest Authentication.user Authentication.app Authentication.action
| rename Authentication.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

- A successful logon on the target from `src` at the time of the command confirms the hop. Check what ran on the target afterwards (EDR process tree on the target).
- `remote_targets` is best effort. If it reads "not parsed", take the host from `remote_commands`.

### Step 4: Identify the user

```spl
| inputlookup identity_lookup_expanded where identity="$user$"
| table identity, first, last, email, managedBy, bunit, category, priority
```

- Does the user administer the target host as part of their job (platform, SRE, DevOps)? Is the target in their area?
- If no user is attributed (Codex sandbox or unknown account), find the person from the host owner or the interactive logons on `src`.

### Step 5: Check for related AI risk and prompt-injection evidence

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object IN ("$user$","$src$") source="*HDSI AI*"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as rules count as events by risk_object, risk_object_type
| sort - total_risk
```

- This rule belongs to the high-impact `adversarial` vector of `Threat - HDSI RBA AI Multi-Vector Risk - Rule`, and to the AI-activity side of `Threat - HDSI RBA AI Privilege Escalation Correlation - Rule`.
- Look for Agent Autonomous Action Detection (credential access, persistence, system change), MCP Server Execution and Prompt Injection Indicators on the same user or host. A recent privilege grant followed by agent-driven remote commands is a strong escalation signal.

### Step 6: Determine sanctioned status

```spl
| inputlookup ai_sanctioned_entities
| where tonumber(enabled)=1 AND (lower(entity)=lower("$user$") OR lower(entity)=lower("$src$") OR entity="*")
| table entity_type, entity, provider, scope, expires, owner, reason, allow_key
```

- Allowlist keys use the lowercased agent provider: `<user>|anthropic` (Claude Code), `<user>|openai` (Codex), `<user>|google gemini` (Gemini CLI, Antigravity), `*|github copilot` (Copilot agents), `<host>|*` (a jump host), `<bunit>|*` (a team).

### Step 7: Make a determination

- **True Positive:** the agent reached a host the user should not reach, ran reconnaissance or offensive tooling, or acted on instructions that came from untrusted content (prompt injection).
- **Benign True Positive:** an engineer deliberately let the agent administer servers they own. Allowlist by user, host or `bunit`.
- **False Positive:** the matched text was not a command (for example an `echo` or `printf` that contains "ssh host"), or a local operation the benign regex does not know. Extend the benign regex.

## True Positive Indicators

- `offensive_tooling=1` (Impacket, NetExec/CrackMapExec, evil-winrm). Treat as a probable compromise.
- Admin-share staging (`\\host\admin$`, `\\host\c$`) or PsExec/WMI execution from a developer workstation.
- The target host is outside the user's normal administrative scope, or is a domain controller or production database.
- Reconnaissance or credential access by the same agent session shortly before the remote command.
- The agent session started from a repository, issue, web page or MCP tool that the user does not control.
- Credentials typed in the command line (`sshpass -p`, `-hashes`, `/user:x <password>`, now shown as `<redacted>`).

## False Positive Scenarios

Evidence is from read-only live tests on 4 production ES tenants (Tenant A-D) on 2026-10-09.

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Sanctioned DevOps or SRE use (agent manages servers by design) | Medium where agents are adopted | Allowlist in `ai_sanctioned_entities` by user, host or `bunit` with the agent provider. Do not widen the benign regex for this |
| Self-hosted Git auth test (`ssh -T git@git.internal`) | Low | Add the internal Git host to `..._benign_regex`, anchored to the ssh destination and ending in `(?![\w.-])` |
| Management tools doing remote registry or admin-share work (Tenant A: 4,140 remote `reg` calls in 30 min from one tool; Tenant C: an inventory script run from `\\host\admin$`) | Low: these only count when an AI agent launched them | None needed; they never fired in validation because no agent was the parent |
| Text that looks like a command (`echo "done; ssh srv01"`, `printf` into a file) | Low | Extend `..._benign_regex` for the specific pattern |
| Claude Desktop shares the `claude`/`claude.exe` process name | Low | Desktop chats do not normally spawn remote commands |

In validation the rule returned 0 rows over 4 hours and 7 days on every tenant. Agent parents were seen on three tenants: Antigravity shells (Tenant A), the Codex Windows runner under a sandbox account (Tenant B) and the VS Code Copilot runtime on 3 hosts with about 1,670 children in 7 days (Tenant C), none launching remote commands. A 177-case regex corpus and a 9-row synthetic pipeline test passed on all four tenants.

## Response Actions

### If confirmed True Positive

1. **Contain:** stop the agent session on `src` and, if offensive tooling or an unexpected target is involved, isolate `src` with the EDR. Disable the account if credentials were exposed or misused.
2. **Notify:** inform the incident response team and the owner of each target host. Inform the user's manager.
3. **Investigate:** reconstruct the agent session (its prompts, the repository or content it was working on, MCP servers and tool outputs) to find the source of the instruction. Review what ran on every target host after the logon.
4. **Remediate:** rotate SSH keys, passwords, hashes or tokens the agent used or exposed (`remote_commands` redacts common credential forms, but check the raw command line). Remove persistence on targets. Restrict which credentials and networks agents can reach (separate agent accounts, no standing admin rights).
5. **Document:** record the findings in the case management system. `remote_commands` is stored in the Risk index; restrict access to it if it contains sensitive values.

### If Benign True Positive

1. Add a row to `ai_sanctioned_entities` (common package) with `allow_key` `<user>|<provider lowercase>`, `<host>|*` or `<bunit>|*`, an expiry date and the justification in `reason`. Check the `provider` field of the risk event before writing the key.
2. If an aggregator notable was raised, close it as Benign True Positive and reference the approval.

## Tuning Guidance

### Reducing false positives

- Allowlist sanctioned agent-driven administration by user, host or team; keep the benign regex for technical non-commands only.
- Add internal Git hosts and sanctioned jump hosts to `..._benign_regex`, anchored to the ssh destination, for example `\bssh(?:\.exe)?\s+(?:[\w.-]+@)?jump01(?![\w.-])` (double each backslash inside the macro's quoted definition).
- If `remote_commands` might carry secrets in your environment, set `..._customizations` to `fields - remote_commands`.

### Adjusting thresholds

There is no numeric threshold. Before enabling, see which agents run on your endpoints and what they launch (7 days):

```spl
| tstats summariesonly=t allow_old_summaries=t count dc(Processes.dest) as hosts dc(Processes.user) as users
    from datamodel=Endpoint.Processes
    where `hdsi_ai_assisted_lateral_movement_agent_parents`
    by Processes.parent_process_name Processes.process_name
| sort - count
```

And which shell or remote-tool command lines the regex would flag regardless of the parent (1 hour). Everything it returns should be a genuine remote operation; if a local command appears, extend the benign regex:

```spl
| tstats summariesonly=t allow_old_summaries=t count from datamodel=Endpoint.Processes
    where Processes.process_name IN ("cmd.exe","powershell.exe","pwsh.exe","bash","zsh","sh","reg.exe","ssh","ssh.exe","net.exe","sc.exe","wmic.exe","mstsc.exe")
    by Processes.process_name Processes.process
| rename Processes.* as *
| eval p=replace(lower(process), `hdsi_ai_assisted_lateral_movement_benign_regex`, " ")
| where match(p, `hdsi_ai_assisted_lateral_movement_remote_regex`)
| stats sum(count) as events by process_name p
| sort - events
```

### Key tuning macros

| Macro | Ships as | Use |
|---|---|---|
| `hdsi_ai_assisted_lateral_movement_filter` | `()` | Inline exclusions in the `tstats` (`Processes.*` names), e.g. `NOT Processes.user IN ("svc_ansible")` |
| `..._agent_parents` | agent binaries, runners, node/bun/python hosts, native installer, Antigravity shells | Which parents count as an AI coding agent; add new agents here |
| `..._remote_regex` | command-position remote-access regex | What counts as remote access |
| `..._benign_regex` | git transport, localhost, version/help, messages, heredocs | Fragments stripped before matching |
| `..._customizations` / `..._risk_score` | `search *` | Post-normalisation hook; last-pipe score override |

### Adding allowlist entries

entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
user,<username>,Anthropic,provider,<YYYY-MM-DD>,<your_name>,<justification>,1,<username>|anthropic
