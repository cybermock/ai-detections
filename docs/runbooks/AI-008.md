# AI-008 - Scripted AI CLI Invocation

> **Detection ID:** AI-008
> **Package:** `hdsi_ai_scripted_cli_invocation` (v1.1.0, `deployment_type: global`)
> **Search name:** `Endpoint - HDSI AI Scripted CLI Invocation - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`, `action.risk = 1`). The package ships with `enable_alerting: false`.
> **Risk Score:** Dynamic, base 20-50 × identity multiplier, capped at 80, applied to both risk objects (`user`, `src`). Literal fallback: user 30, system 20.
> **MITRE ATT&CK:** T1059 - Command and Scripting Interpreter (Execution)
> **Data Model:** Endpoint.Processes
> **Schedule:** `23 * * * *` (hourly)
> **Lookback Window:** `-65m@m` to `-5m@m`
> **Suppression:** 24 hours per `user`,`src`
> **Kill Chain Phase:** `execution` (RBA vector `local_tooling` in the multi-vector aggregator)
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds **AI command-line agents that start without a person at the keyboard**. Covered tools include Claude Code, OpenAI Codex, Gemini CLI, GitHub Copilot CLI, Qwen Code, Amazon Q, Aider, `llm` and `sgpt`, whether they run as their own binary, inside `node` (npm installs), inside `python` (pip, pipx and uv installs) or as a native Claude Code install whose image name is a version number.

A run counts as unattended in four cases:

- a script interpreter, build tool or orchestrator launched it;
- another AI agent launched it;
- it ran headless (`claude -p`, `codex exec`, `gemini -p`, `aider --message`);
- it ran with a flag that switches off the agent's approval prompts or sandbox (`--dangerously-skip-permissions`, `--yolo`/`-y`, `--trust-all-tools`, `-s danger-full-access`, `--ask-for-approval never`).

An unattended agent carries the user's credentials, file access and network position, and nobody reviews the commands it runs. The August 2025 Nx "s1ngularity" npm compromise showed the abuse case: a `postinstall` script called the victim's own `claude`, `gemini` and `q` CLIs with these bypass flags to search the disk for secrets. Most hits in a real estate will be sanctioned automation (CI code review, git hooks); the bypass-flag cases deserve a look even then.

The rule creates no notable.

## Detection Logic

### Plain English

1. `tstats` over `Endpoint.Processes` selects AI CLI executable names, `node`/`bun`/`deno` running an npm-installed AI CLI, `python*` running a pip-installed Aider/`llm`/`sgpt`, native Claude Code (a version-number image with a `claude` command line) and Amazon Q `q chat`. Rows are grouped by `user`, `dest`, `parent_process_name`, `parent_process`, `process_name` and `process`.
2. Map each process to a canonical tool key (`claude`, `codex`, `gemini`, `gh-copilot`, `qwen`, `aider`, `llm`, `sgpt`, `amazon-q`).
3. Drop name collisions (`..._name_collision_check`): macOS `.app` bundles, the Claude desktop app and its bundled Claude Code, Store apps and Microsoft Service Fabric `Fabric.exe`.
4. Keep tools enabled with `usage_type=cli` in the common `ai_tool_processes` lookup (`ai_process_filter`).
5. Classify the parent: `none`, `ide` (local IDE or remote extension host), `cli_relaunch` (the CLI relaunching itself), `ai_agent` (a different AI CLI), `npm_launcher`, `package_runner` (`npx`, `uvx`, `pipx`...), `automation` (script interpreters, build tools, orchestrators) or `shell_or_other`.
6. Check the command line for **headless** flags and subcommands (`--print`, `--prompt`, `--message`, `--output-format`, `codex exec`, and `-p` only for tools where it means print) and for **bypass** flags. One-shot chat CLIs (`llm`, `sgpt`, `fabric`...) are never headless on their own.
7. Keep a row when it has a bypass flag (any parent), or its parent is automation or another AI agent, or it ran headless and its parent is not an IDE.
8. Non-human accounts (`..._nonhuman_users`: `SYSTEM`, service principals, `HOST$`) get system risk only. Approved users, hosts and groups are removed with `ai_unsanctioned_filter`. Rows roll up to one per `user` + `src`.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `user` / `user_display` | Account, or "an unattributed account" for non-human accounts | `jdoe` |
| `src` | Host (`Processes.dest`) | `dev-ws-042` |
| `tools` / `providers` | Canonical tools and their providers | `claude` / `Anthropic` |
| `reasons` | Why it counted | `permission bypass, launched by an automation parent` |
| `parent_processes` / `parent_class` | Parent executable and its class | `node` / `automation` |
| `process` | Up to 5 command lines | `claude --dangerously-skip-permissions -p "..."` |
| `count` | Launches in the window | `3` |
| `base`, `risk_multiplier`, `risk_score` | Scoring | `50`, `1.0`, `50` |

### Risk scoring

`risk_score = min(80, round(base × risk_multiplier))`, applied to both risk objects.

| Condition | Base |
|---|---|
| Automation parent or another AI agent, and a bypass flag | 50 |
| Bypass flag, any other parent (including an IDE) | 40 |
| Automation parent or another AI agent, headless | 35 |
| Automation parent or another AI agent | 30 |
| Headless run from a shell, package runner, self-relaunch or with no parent | 20 |

`risk_multiplier` (1.0-2.0) is the identity `bunit` sensitivity × 1.25 for privileged identities.

### Thresholds

None. Every unattended invocation is reportable. Volume is bounded by the 24-hour suppression on `user,src`.

## Triage Steps

> **Estimated triage time:** 10-20 minutes

Replace `<src>`, `<user>`, `<parent_process_name>` and `<risk_object>` with values from the risk event.

### Step 1: Read the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Endpoint - HDSI AI Scripted CLI Invocation - Rule" risk_object="<risk_object>"
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- `reasons` decides the urgency: **permission bypass** first, then **launched by another AI agent / an automation parent**, then **headless one-shot run**.
- A system-only event means the account was `SYSTEM`, a service principal or a machine account.

### Step 2: List the AI CLI launches on the host

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime from datamodel=Endpoint.Processes where Processes.dest="<src>" (Processes.process_name IN (`hdsi_ai_scripted_cli_invocation_cli_names`) OR Processes.process IN (`hdsi_ai_scripted_cli_invocation_node_cli_patterns`) OR Processes.process IN (`hdsi_ai_scripted_cli_invocation_native_cli_patterns`) OR Processes.process IN (`hdsi_ai_scripted_cli_invocation_python_cli_patterns`)) by Processes.user Processes.parent_process_name Processes.parent_process Processes.process_name Processes.process
| rename Processes.* as *
| sort - lastTime
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user parent_process_name parent_process process_name process count
```

- Read the full command line: the flags, the prompt text and the working directory.
- A prompt that asks the agent to search for files, keys, wallets, tokens or `.env` files, or to send results somewhere, is the s1ngularity pattern.

### Step 3: Find what launched the parent

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime from datamodel=Endpoint.Processes where Processes.dest="<src>" Processes.process_name="<parent_process_name>" by Processes.user Processes.parent_process_name Processes.process_name Processes.process
| rename Processes.* as *
| sort - lastTime
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user parent_process_name process_name process count
```

- An `npm install`/`postinstall`, `node_modules` path or a freshly downloaded script in the grandparent chain is the supply-chain pattern. Compare with the package-install times on the host.
- A CI agent (`Runner.Worker`, `gitlab-runner`, `buildkite-agent`), cron or a known orchestrator points to approved automation; confirm with the pipeline owner.

### Step 4: See what the agent ran

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime from datamodel=Endpoint.Processes where Processes.dest="<src>" (Processes.parent_process_name IN (`hdsi_ai_scripted_cli_invocation_cli_names`) OR Processes.parent_process IN (`hdsi_ai_scripted_cli_invocation_node_cli_patterns`)) by Processes.user Processes.parent_process_name Processes.process_name Processes.process
| rename Processes.* as *
| eval suspicious=if(match(lower(process),"\.ssh|\.aws|\.azure|\.config/gcloud|\.env\b|id_rsa|\.pem|wallet|keychain|gh auth token|printenv|curl |wget |invoke-webrequest|base64"),1,0)
| sort - suspicious - lastTime
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user parent_process_name process_name process suspicious count
```

- Agents usually run their commands through `bash -c`, `sh -c` or PowerShell; look at those command lines.
- Credential paths, environment dumps, token commands or outbound transfers (`suspicious=1`) after a bypass-flag launch are a true-positive pattern.
- Children of a version-named native Claude Code process are not listed here; search by the host and time window if the CLI is a native install.

### Step 5: Identify the user and check approvals

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy bunit category priority
```

```spl
| inputlookup ai_sanctioned_entities
| search allow_key="<user>|*" OR allow_key="<src>|*"
| table entity_type entity provider scope expires owner reason enabled allow_key
```

- Developers and build accounts run AI CLIs legitimately. The question is whether *this* automation is approved.

### Step 6: Check related AI risk

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object="<risk_object>" source="* - HDSI AI * - Rule"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources min(_time) as first_seen max(_time) as last_seen by risk_object risk_object_type
| convert ctime(first_seen) ctime(last_seen)
```

- `Endpoint - HDSI AI Agent Autonomous Action Detection - Rule` shows what an agent did once started (credential access, persistence, system change).
- `Endpoint - HDSI AI MCP Server Execution - Rule` and `Endpoint - HDSI AI Agent Framework Execution - Rule` show the wider agent tooling on the host.

### Step 7: Make a determination

- **True Positive:** an AI CLI launched by an unknown script or package install, especially with a bypass flag, or followed by credential access or outbound transfer.
- **Benign True Positive:** approved CI review jobs, scheduled reports, git hooks, or a developer typing `claude -p` / `codex exec`.
- **False Positive:** a process that only shares a name with an AI CLI, or an IDE layout the rule does not recognise.

---

## True Positive Indicators

- A bypass flag (`--dangerously-skip-permissions`, `--yolo`, `-y`, `--trust-all-tools`, `danger-full-access`, `--ask-for-approval never`) on a host or account with no approved AI automation.
- The grandparent is a package manager install (`npm install`, `postinstall`, a `node_modules` script) or a file downloaded shortly before.
- Several AI CLIs started in sequence on the same host (s1ngularity tried `claude`, `gemini` and `q` one after the other).
- Child processes read credential stores, dump the environment, call `gh auth token`, or upload data.
- Public reporting on s1ngularity also describes a `/tmp/inventory.txt` result file and shell profile changes (`sudo shutdown -h 0` appended to `~/.bashrc`/`~/.zshrc`); check file and profile changes where you have filesystem telemetry.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Sanctioned CI or review bots (`claude -p`, `codex exec`) | High where developers use AI CLIs | Add a system or user `ai_sanctioned_entities` entry, or `NOT Processes.dest IN ("ci-runner-*")` in `..._filter` |
| A developer typing a headless command at a terminal (scores 20) | Medium | Lower headless scores in `..._risk_score`, e.g. `eval risk_score=if(match(reasons,"bypass"),risk_score,10)` |
| An IDE remote layout not in `..._ide_host_cmd` (shows as `node` automation parent, 30-35) | Low | Add its folder or command line to `..._ide_host_cmd` |
| A `node` script launching a Node-hosted CLI where `parent_process` is not collected (treated as a self-relaunch, scored on flags only) | Low | Collect the parent command line |
| Name collisions (`Fabric.exe` Service Fabric, ~61k events in 7 days on Tenant A) | Removed | Already dropped by `..._name_collision_check`; extend it for collisions in your estate |

## Response Actions

### If confirmed True Positive

1. **Contain:** Isolate the host. Stop the agent process and the script that launched it.
2. **Rotate:** Treat every credential the account and host could reach as exposed: SSH keys, cloud CLI credentials, GitHub and npm tokens, browser-stored secrets, `.env` files. Revoke and reissue.
3. **Investigate:** Identify the package or script that started the agent and every host where it was installed. Check for outbound transfers and new public repositories under the user's source-control account.
4. **Remediate:** Remove the malicious package, pin dependencies, and disable bypass flags through managed settings where the CLI supports it.
5. **Document:** Record the command lines, the launch chain, the exposed credentials and the rotation tickets.

### If Benign True Positive

1. Add the CI runner, build account or approved group to `ai_sanctioned_entities` with an expiry date:
   ```
   entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
   system,ci-runner-01,*,global,2027-06-30,devops,code-review pipeline,1,ci-runner-01|*
   user,svc_build,Anthropic,provider,2027-06-30,devops,nightly review job,1,svc_build|anthropic
   ```
   Prefer system or user entries for CI. An organisation-wide or group entry also hides the bypass-flag cases for that provider.
2. Close the finding as Benign True Positive.

## Tuning Guidance

### Reducing false positives

- Allowlist approved automation in `ai_sanctioned_entities` (`provider` is the `ai_tool_processes` provider: `Anthropic`, `OpenAI`, `Google Gemini`, `Microsoft Copilot`, `Alibaba Qwen`, `Amazon`, `Aider`, `LLM CLI`, `Shell GPT`; `allow_key` lowercase).
- Add your service-account convention to `..._nonhuman_users` (e.g. `|svc[-_.].*`) so those accounts carry system risk only.
- Add orchestration hosts to `..._automation_parents` (e.g. `airflow`). Keep shells, `svchost.exe` and package runners out of it.
- Add new vendor bypass flags to `..._bypass_flags` as they ship.
- Do not remove `..._name_collision_check`.

### Adjusting thresholds

No count threshold. Before enabling, run the saved search over 7 days and review the `parent_class` and `reasons` columns:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count from datamodel=Endpoint.Processes where (Processes.process_name IN (`hdsi_ai_scripted_cli_invocation_cli_names`) OR Processes.process IN (`hdsi_ai_scripted_cli_invocation_node_cli_patterns`)) by Processes.dest Processes.parent_process_name Processes.process_name
| rename Processes.* as *
| stats sum(count) as launches dc(dest) as hosts values(parent_process_name) as parents by process_name
| sort - launches
```

### Tuning macros

| Macro | Ships as | Purpose |
|---|---|---|
| `hdsi_ai_scripted_cli_invocation_filter` | `()` | Exclusions inside the `tstats` where clause (`Processes.*` names) |
| `..._cli_names`, `..._js_hosts`, `..._py_hosts`, `..._native_version_names`, `..._amazon_q_names` | 40 names / host runtimes | What the `tstats` selects |
| `..._node_cli_patterns`, `..._python_cli_patterns`, `..._native_cli_patterns` | command-line wildcards | Hosted and native CLI command lines |
| `..._automation_parents`, `..._package_runners`, `..._ide_parents`, `..._ide_host_cmd` | regexes | Parent classification |
| `..._unattended_flags`, `..._unattended_subcommands`, `..._short_p_tools`, `..._chat_clis` | regexes / lists | Headless detection |
| `..._bypass_flags` | regex | Approval and sandbox bypass flags |
| `..._name_collision_check` | `where NOT match(cmd_lc, ...)` | Drops look-alike processes |
| `..._nonhuman_users` | regex | Accounts that get system risk only |
| `..._customizations` / `..._risk_score` | `search *` | Post-aggregation hook / last-pipe score override |
