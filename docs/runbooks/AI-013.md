# AI-013 - LLM Model File Download

> **Detection ID:** AI-013
> **Package:** `hdsi_ai_llm_model_file_download` (v1.1.0, deployment type `global`, ships `enable_alerting: false`)
> **Search name:** `Network - HDSI AI LLM Model File Download - Rule`
> **Status:** Active (risk-only: `action.risk = 1`, `action.notable = 0`)
> **Risk Score:** dynamic `risk_score = min(60, max(10, round(base x risk_multiplier)))`, base 40 (large download), 30 (model hub client or weight-file URL) or 20 (bulk CDN fetch only), +10 when two or more evidence types agree. Applied to `user` and `src` (system), whichever is known. Literal `_risk` fallback 30 per object
> **MITRE ATT&CK:** T1588.007 - Obtain Capabilities: Artificial Intelligence (Resource Development); T1105 - Ingress Tool Transfer (Command and Control)
> **Data Model:** `Web` OR `Network_Resolution` (DNS)
> **Schedule:** `41 1 * * *` (daily at 01:41)
> **Lookback Window:** `-1d@d` to `@d` (the previous calendar day)
> **Suppression:** 23 hours (`82800s`) on `user,src`
> **Kill Chain Phase:** `staging` (multi-vector aggregator vector: `local_tooling`)
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds a user or host fetching LLM model weights from Hugging Face, ModelScope or the Ollama registry, using Web (proxy, SSE or URL-filtering firewall) and DNS evidence. Visiting the hub web sites never counts: the rule needs a model hub client, a weight-file download URL, a large download or a bulk fetch from the model storage CDNs.

A downloaded model runs outside every sanctioned AI control: no DLP, no provider contract, no prompt logging. Pickle-based `.bin`/`.pt` checkpoints can also carry executable code. The rule creates risk on the `user` and on the host (`src`, system), whichever is known, and no notable. Running the model is covered by AI-011 (process execution) and AI-014 (listening port).

Typical actors: developers and data scientists pulling models for local experiments (often legitimate); users installing Ollama or LM Studio and pulling a chat model; occasionally a user pushing a model or dataset to a public hub, which is the more serious case (see "Uploads look like downloads").

## Detection Logic

### Plain English

1. **Shared-source guard (outer search):** find DNS clients that resolved at least `_shared_src_names` (10,000) distinct names in the day. Resolvers, forwarders and egress addresses are dropped from every branch, so a model download is never put on a DNS server.
2. **Web branch (appended):** `tstats` over `Web` limited by `_web_scope` (model hub hosts in `url_domain` or `site`, plus SSE app names such as "Hugging Face") and `_filter`, with `fillnull_value="unknown"`. `ai_domain` is `url_domain`, or `site` when no domain is logged. The URL path is tested against `_weight_file_pattern`, and `model_file` is extracted.
3. **DNS branch (appended):** `tstats` over `Network_Resolution` limited by `_dns_scope`: only the names that serve weights (Hugging Face LFS and Xet storage, ModelScope LFS, the Ollama registry and its Cloudflare R2 blob bucket). Trailing-dot names are handled; query and response logs are counted once.
4. Map the Ollama blob bucket to `registry.ollama.ai`, resolve providers with `ai_domains_filter`, and keep `usage_type` `model_registry` (Hugging Face, ModelScope) or `local_llm` (Ollama). Hugging Face inference API hosts are not counted.
5. Identity: placeholder users become null. A `src` matching `_untrusted_src` (public IPv4) or `_unstable_src` (IPv6; `192.168.0.0/16` from roaming DNS-security agents) is never a risk object, and such rows without a user are dropped. A DNS row with no user is credited to a Web user only if exactly one user made model-hub Web requests from that host that day and the lookups fall within one hour of that activity.
6. Evidence per user (or host when no user):
   - **Model hub client** (`tool_events`): any request or lookup for `cas-server`/`transfer.xethub*.hf.co` or `registry.ollama.ai`. Browsers do not use them.
   - **Weight-file URL** (`weight_events`): a `/resolve/<revision>/<file>` download of `.gguf`, `.safetensors`, `.bin`, `.pt`, `.onnx` and similar, a ModelScope `FilePath=` download, or an Ollama blob pull. File viewer pages (`/blob/`, `/tree/`), configs, datasets and training-state files do not count.
   - **Large download:** at least `_min_mb` (500 MB) of `bytes_in` from model hub hosts.
   - **Bulk model-CDN fetch** (`cdn_events`): at least `_min_cdn_events` (25) CDN requests or lookups.
7. Remove sanctioned entities, emit each host as a system risk object at most once a day, apply `ai_risk_multiplier` (user identity only; host-only rows score with 1.0) and score.

## Triage Steps

> **Estimated triage time:** 10-20 minutes. Replace `$risk_entity$` (user or host) and `$src$` with values from the risk event; for a user row with several hosts use each host from `src_display`. The rule covers the previous day, so set the time picker to the last 2 days.

### Step 1: Read the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Network - HDSI AI LLM Model File Download - Rule" (risk_object="$risk_entity$" OR risk_object="$src$")
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- The message gives the model source, user, host, evidence types, counts, weight files and MB received.
- "model hub client" alone means a Hugging Face Xet client or the Ollama registry was used; this can be a pull **or a push**.

### Step 2: Review the model hub Web activity

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count sum(Web.bytes_in) as bytes_in sum(Web.bytes_out) as bytes_out values(Web.http_method) as http_method values(Web.status) as status min(_time) as firstTime max(_time) as lastTime
    from datamodel=Web
    where (Web.user="$risk_entity$" OR Web.src="$risk_entity$" OR Web.src="$src$") `hdsi_ai_llm_model_file_download_web_scope` earliest=-2d@d
    by sourcetype Web.user Web.src Web.url_domain Web.site Web.url
| rename Web.* as *
| eval url_domain=coalesce(nullif(url_domain,"unknown"),site), mb_in=round(bytes_in/1048576,2), mb_out=round(bytes_out/1048576,2)
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user src url_domain url http_method status count mb_in mb_out sourcetype
| sort - count
```

- Which model repositories and files (`/resolve/.../*.gguf`, `*.safetensors`, Ollama `/v2/<name>/blobs/sha256:...`)?
- **Direction:** large `mb_out` or `PUT`/`POST` to `cas-server.xethub.hf.co` or `registry.ollama.ai` is an **upload** (model or dataset push). Escalate that as possible exfiltration.
- `url_domain` falls back to the SSE app name in `site` when the product logs no hostname.

### Step 3: Review the model download DNS lookups

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime
    from datamodel=Network_Resolution
    where (DNS.src="$risk_entity$" OR DNS.src="$src$") `hdsi_ai_llm_model_file_download_dns_scope` earliest=-2d@d
    by DNS.src DNS.query sourcetype
| rename DNS.* as *
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime src query count sourcetype
| sort - count
```

- `cas-server`/`transfer.xethub*.hf.co` = Hugging Face client (`huggingface_hub`, `transformers`, LM Studio). `registry.ollama.ai` or the R2 bucket = Ollama pull/push. `cdn-lfs*` / `cas-bridge` / `*.cdn.hf.co` in bulk = file download.
- Confirm the `src` is a single endpoint, not a resolver, VPN pool or roaming address.

### Step 4: Find the client on the endpoint

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime values(Processes.process) as process values(Processes.parent_process_name) as parent_process_name
    from datamodel=Endpoint.Processes
    where Processes.dest="$src$" earliest=-2d@d (Processes.process_name IN ("ollama*","lm studio*","lmstudio*","huggingface-cli*","hf","hf.exe","git-lfs*") OR Processes.process IN ("*huggingface*","*hf_hub*","*ollama pull*","*ollama push*","*ollama run*","*push_to_hub*","*modelscope*"))
    by Processes.dest Processes.user Processes.process_name
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

- `ollama pull`/`run`, `huggingface-cli download`/`hf download` or Python fetching models = download. `ollama push`, `huggingface-cli upload`, `hf upload` or `push_to_hub` = upload.
- Note `src` may be an IP address in network data while `Processes.dest` is a host name; resolve it with `asset_lookup_by_str` first if needed.

### Step 5: Correlate with local LLM execution and other AI risk

```spl
| from datamodel:"Risk.All_Risk"
| search (risk_object="$risk_entity$" OR risk_object="$src$") source="* - HDSI AI * - Rule"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources values(ai_kill_chain_phase) as phases by risk_object risk_object_type
| sort - total_risk
```

- AI-011 (`Endpoint - HDSI AI Local LLM Framework Execution - Rule`) or AI-014 (`Network - HDSI AI Local LLM Listening Port Detected - Rule`) on the same user or host completes the picture: model obtained and run locally.

### Step 6: Identify the owner and check sanctioned status

```spl
| inputlookup asset_lookup_by_str
| search ip="$src$" OR dns="$src$" OR nt_host="$src$"
| table ip dns nt_host owner bunit category priority
```

```spl
| inputlookup ai_sanctioned_entities
| where enabled=1 AND (lower(entity)=lower("$risk_entity$") OR lower(entity)=lower("$src$") OR entity="*" OR entity_type="group") AND (provider="*" OR lower(provider) IN ("model registry","local llm"))
| table entity_type entity provider scope expires owner reason allow_key
```

### Step 7: Make a determination

- **True Positive:** an unapproved user or host downloaded model weights, or pushed a model or dataset to a public hub.
- **Benign True Positive:** approved data-science or engineering work. Allow-list it with an expiry.
- **False Positive:** the `src` is not one endpoint (resolver, VPN or roaming address), or the "user" value is not a person. Tune the source handling.

---

## True Positive Indicators

- Weight-file URLs or Ollama blob pulls from a workstation in a business unit with no AI approval.
- Large downloads (hundreds of MB to GB) followed by AI-011 or AI-014 on the same host.
- `bytes_out` to `cas-server.xethub.hf.co` or `registry.ollama.ai`, or `push_to_hub`/`ollama push`/`hf upload` on the endpoint (upload of an internal model or data).
- Pickle-format checkpoints (`.bin`, `.pt`, `.pth`, `.ckpt`) from unknown repositories on a sensitive host.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Internal DNS resolvers appear as the client (every DNS hit on Tenant A came from three resolvers with 108,000-380,000 names a day) | High without the guard | Dropped by the shared-source guard. List resolvers below 10,000 names a day in `_dns_filter` |
| Inbound WAF/load-balancer logs carry internet scanners sending `Host: <uuid>.xethub.hf.co` (more than 600 source-days a week on Tenant B) | High in tenants with inbound Web data | Dropped (public `src`, no user). Also exclude those sourcetypes in `_filter`: `NOT sourcetype IN ("aws:waf","aws:elb:accesslogs")` |
| Roaming DNS agents log home-network `192.168.x.x` or IPv6 addresses shared by unrelated laptops (Tenant B) | Medium | `_unstable_src` covers IPv6 and `192.168.0.0/16` from Cisco Umbrella / Secure Access sourcetypes. Add other agents or ranges |
| VPN, DHCP or CGNAT pool address carries host-only risk that later reads as someone else's | Medium | Mark the pool untrusted in `_untrusted_src`, or get the VPN user into Web/DNS data |
| Model card browsing fetches a few CDN images | Low | Below `_min_cdn_events` (25). Keep it above your CDN-only p95 and max |
| Ordinary data-science fetches of embedding models, or `transformers.js` web apps fetching small `.onnx` files | Medium | Allow-list data-science groups (`<bunit>|model registry`) |
| A DNS-security proxy maps an identity string (`<device>,<site>`) into `user` | Low | Fix the field mapping in the add-on |

## Response Actions

### If confirmed True Positive

1. **Contain:** block the model hub client hosts (`*.xethub.hf.co`, `registry.ollama.ai`, the Ollama R2 bucket) and `/resolve/` downloads for the user or host at the proxy/DNS layer if policy forbids local models. For an **upload**, block the destination at once and preserve proxy and endpoint evidence.
2. **Notify:** the user's manager and AI governance owner; for an upload, the data owner and incident response.
3. **Investigate:** identify the models and repositories (Steps 2-4), whether the model ran locally (AI-011, AI-014), and, for pickle-format files, scan them before anyone loads them. For an upload, identify the repository and what it contains.
4. **Remediate:** remove unapproved models and runtimes, or move the work to a sanctioned platform or an internal model mirror. For an upload, request takedown of the repository and rotate any secrets it contained.
5. **Document:** record model source, files, direction and disposition.

### If Benign True Positive

1. Add the user, host or `bunit` group to `ai_sanctioned_entities` with provider `Model Registry` (Hugging Face, ModelScope), `Local LLM` (Ollama) or `*`, and an `expires` date, for example:
   ```
   entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
   group,data science,Model Registry,group,2027-03-31,<owner>,<approved model research>,1,data science|model registry
   ```
2. A `*|model registry` row allows Hugging Face and ModelScope for the whole organisation.

## Tuning Guidance

### Reducing false positives

- Run the resolver query below over one full day; make sure the guard catches your resolvers and list smaller forwarders in `_dns_filter`.
- Decide how VPN pools and roaming DNS agents are handled (`_untrusted_src`, `_unstable_src`). Use `false()` in `_untrusted_src` if clients have public addresses.
- Exclude inbound server sourcetypes in `_filter` (they add scan time and no signal).
- Allow-list sanctioned data-science users, groups and GPU hosts in `ai_sanctioned_entities`.
- Override the score at the last pipe with `hdsi_ai_llm_model_file_download_risk_score` (it applies to both risk objects; keep it at or below 100).

### Adjusting thresholds

Find resolvers and forwarders (candidates for the guard or `_dns_filter`):

```spl
| tstats summariesonly=t allow_old_summaries=t dc(DNS.query) as names
    from datamodel=Network_Resolution
    where NOT DNS.src IN ("unknown","-","0.0.0.0","127.0.0.1","::1") earliest=-1d@d latest=@d
    by DNS.src
| where names>=2000
| sort - names
```

Then check the CDN-only shape over 7 days (the package README has the full Web + DNS version). Keep `_min_cdn_events` above the CDN-only p95 and max:

```spl
| tstats summariesonly=t allow_old_summaries=t count
    from datamodel=Network_Resolution
    where `hdsi_ai_llm_model_file_download_dns_scope` NOT DNS.src IN ("unknown","-") `hdsi_ai_llm_model_file_download_dns_filter` earliest=-7d@d latest=@d
    by _time span=1d DNS.src DNS.query DNS.message_type
| stats max(count) as count by _time DNS.src DNS.query
| rename DNS.* as *
| eval host=replace(lower(query),"\.$","")
| eval tool=if(match(host,`hdsi_ai_llm_model_file_download_tool_hosts`),count,0), cdn=if(match(host,`hdsi_ai_llm_model_file_download_cdn_hosts`),count,0)
| stats sum(tool) as tool sum(cdn) as cdn by _time src
| where cdn>0
| eval day_type=if(tool>0,"with model hub client","CDN only")
| stats count as host_days dc(src) as hosts perc95(cdn) as p95_cdn max(cdn) as max_cdn by day_type
```

### Scope

Model downloads from GitHub releases, Kaggle, Civitai, Replicate, cloud object storage, container images or internal mirrors are not detected. Add a hub to `_web_scope`, `_dns_scope` and the common lookups together.
