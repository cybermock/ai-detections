# AI-005 - HDSI AI Unsanctioned Desktop App Execution

> **Detection ID:** AI-005
> **Package:** `hdsi_ai_unsanctioned_desktop_app_execution` v1.1.0 (deployment type: global)
> **Search name:** `Endpoint - HDSI AI Unsanctioned Desktop App Execution - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`). Notables come from the HDSI RBA AI aggregators.
> **Risk:** `user` (when the account is a person) and `src` system, same dynamic score on both: base 25 for agentic tools, 20 for chat clients and AI IDEs, x `risk_multiplier`, capped at 50. The literal fallback is 20/20.
> **MITRE ATT&CK:** T1588.007 - Obtain Capabilities: Artificial Intelligence (Resource Development)
> **Data Model:** Endpoint.Processes
> **Schedule:** `23 * * * *` (hourly at :23)
> **Lookback Window:** `-65m@m` to `-5m@m`
> **Suppression:** 24 h per `user` + `src`
> **AI kill-chain phase:** `execution` (multi-vector aggregator: `local_tooling`)
> **Last Updated:** 2026-10-09

---

## Overview

This rule detects endpoints running an AI desktop application that has not been sanctioned. It covers three classes:

| `app_class` | Tools |
|---|---|
| `chat_client` | ChatGPT, Claude, Perplexity, Pieces OS, Msty, AnythingLLM |
| `ai_ide` | Cursor, Windsurf, Trae, Kiro |
| `agentic` | ChatGPT Atlas, Perplexity Comet, the Claude Agent SDK bundled inside a third-party application |

Desktop clients send prompts, pasted data, files and whole code repositories straight to the provider, outside the browser. Web and CASB controls that inspect only browser traffic do not see that. Agentic tools can also read and act with the user's sessions.

Electron helper processes (for example `Comet Helper`) count as the app. Short or generic names (`claude`, `trae`, `kiro`, `comet`) need corroboration from the process path. IDE-hosted GitHub Copilot runtimes are excluded by path. The Claude Code CLI is not scored here; AI-004 covers it.

v1.1.0 fixes several gaps:
- The Windows Claude desktop app was never detected before.
- Helper-only processes, such as the only real hit in validation (a Perplexity Comet session on macOS), were missed.
- Group allowlisting never worked, because `bunit` was not looked up first.
- Generic names that collided with other software (`zed`, `warp`, `continue`, `jan`) were matched.

## Detection Logic

### Plain English

1. `tstats` on `Endpoint.Processes` for the executable names in `hdsi_ai_unsanctioned_desktop_app_execution_process_names` (38 names, including every `<app> helper*` form). Results are grouped by `user`, `dest`, `process_name` and `process_path`, with `fillnull_value="unknown"`. Grouping by path means each install location is judged on its own.
2. `hdsi_ai_unsanctioned_desktop_app_execution_signature` maps each row to `tool`, `provider` and `app_class`. `claude.exe` counts as Claude desktop only under `AnthropicClaude`, `Claude.app` or a `WindowsApps` Claude package, and as the Claude Agent SDK only under `claude-agent-sdk`. Trae, Kiro and Comet need their install folder or `.app` bundle. Rows it cannot map are dropped.
3. Drop IDE-hosted Copilot runtimes by **path only** (`_ide_host_exclusion`): `agent-host\sdk-cache\`, `.vscode` `extensions\github.copilot*`, `copilot-language-server`.
4. Normalise service and machine accounts to an empty user, so no `unknown` user collects risk. Drop rows with no host.
5. Look up the identity `bunit`. Then remove approved user, host, `bunit` or organisation-wide entries with `ai_unsanctioned_filter(user,src,provider)`.
6. Roll up to one row per `user` + `src`, listing every tool, provider, process name and up to five paths and command lines. `app_class` is the most severe one seen.
7. Score: `risk_score = min(50, round((25 if agentic else 20) x risk_multiplier))`. ES applies it to both risk objects.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `user` / `user_display` | Person account (null for service, machine and `_service` accounts) | `jdoe@example.com` |
| `src` | Endpoint | `MAC-JDOE-01` |
| `tools` / `providers` | Tools and providers seen | `Perplexity Comet` / `Perplexity` |
| `app_class` | `agentic`, `ai_ide` or `chat_client` | `agentic` |
| `process_names` / `process_path` / `process` | Executables, up to 5 paths and command lines | `Comet Helper` / `/Applications/Comet.app/...` |
| `parent_process_name` | Parent(s) | `Comet` |
| `bunit` / `risk_multiplier` / `risk_score` | Identity group, multiplier (1.0 to 2.0) and score | `sales` / `1.0` / `25` |
| `count` / `firstTime` / `lastTime` | Process events in the window | `12` |

### Thresholds

None. Any execution of a catalogued AI desktop app by a non-sanctioned user or host is reportable. Volume is bounded by the 24-hour suppression on `user,src`.

## Triage Steps

> **Estimated triage time:** 5-10 minutes. This rule raises no notable. You normally reach it from an HDSI RBA AI aggregator notable or from a user's or host's risk timeline.

Replace `<user>`, `<host>` and `<host_ip>` with values from the risk event.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Endpoint - HDSI AI Unsanctioned Desktop App Execution - Rule" (risk_object="<user>" OR risk_object="<host>")
| table _time risk_object risk_object_type risk_score tools providers app_class risk_message
| sort - _time
```

- `agentic` tools (Atlas, Comet, an embedded Agent SDK) carry a higher base score than chat clients and AI IDEs.

### Step 2: Identify the user and the host

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy bunit category priority watchlist
```

```spl
| inputlookup asset_lookup_by_str
| search nt_host="<host>" OR dns="<host>*"
| table nt_host dns ip owner bunit category priority
```

### Step 3: Review the desktop app process activity on the host

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime values(Processes.process_path) as process_path values(Processes.process) as process values(Processes.parent_process_name) as parent_process_name
    from datamodel=Endpoint.Processes
    where Processes.dest="<host>" Processes.process_name IN (`hdsi_ai_unsanctioned_desktop_app_execution_process_names`)
    by Processes.dest Processes.user Processes.process_name
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime dest user process_name process_path process parent_process_name count
| sort - count
```

- Check the install path. A per-user install under `AppData` or `~/Applications` suggests self-installed software. A managed path (`Program Files`, `/Applications` deployed by MDM) suggests IT deployment, which may be sanctioned.
- A `claude.exe` under a third-party application's `claude-agent-sdk` folder means that application embeds an AI agent. Identify the vendor application.

### Step 4: Confirm network use of the provider

The DNS model is keyed by IP. Resolve the host's IP with Step 2 first.

```spl
| tstats summariesonly=t allow_old_summaries=t count from datamodel=Network_Resolution.DNS
    where DNS.src="<host_ip>" by DNS.query
| rename DNS.query as ai_domain
| eval ai_input_type="dns"
| `ai_domains_filter`
| stats sum(count) as queries values(ai_domain) as ai_domains by provider usage_type
| sort - queries
```

### Step 5: Check related detections and sanctioned status

```spl
| from datamodel:"Risk.All_Risk"
| search (risk_object="*<bare user>*" OR risk_object="<host>") source="* - HDSI *"
| stats count as risk_events sum(risk_score) as total_risk values(source) as detections by risk_object risk_object_type
| sort - total_risk
```

```spl
| inputlookup ai_sanctioned_entities
| eval k=lower(allow_key)
| where like(k, lower("<user>|%")) OR like(k, lower("<host>|%")) OR like(k, lower("<bunit>|%")) OR like(k, "*|%")
| table entity_type entity provider scope expires owner reason enabled allow_key
```

### Step 6: Make a determination

- **True Positive:** an AI desktop client, AI IDE or agentic browser that is not approved runs on a corporate endpoint. This is especially serious for agentic tools on hosts with access to sensitive systems.
- **Benign True Positive:** a licensed rollout (for example Cursor for engineering, ChatGPT or Claude enterprise desktop) whose approval is not yet in `ai_sanctioned_entities`.
- **False Positive:** a path or name collision the signature should not have accepted, for example a renamed binary in an unrelated folder.

---

## True Positive Indicators

- Self-installed (per-user path) and not on the approved software list.
- An agentic browser (Atlas, Comet) on a host with access to finance, HR, source code or admin consoles.
- An unknown third-party application embedding the Claude Agent SDK.
- Other risk on the same user: unsanctioned web access to the same provider, uploads, DLP hits.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Licensed AI IDE or desktop client rollout | High where adopted | `<bunit>\|<provider>` or `*\|<provider>` in `ai_sanctioned_entities` |
| VS Code Copilot agent host running the Claude Agent SDK (the only Windows desktop-class process in 30 days across all tenants, on one Tenant C build server) | Excluded by default | `_ide_host_exclusion`. Set it to `false()` if Copilot agent mode is unsanctioned |
| Microsoft 365 Copilot, Windows Copilot, GitHub Copilot language server | Not catalogued | Add them to the catalogue macros only if policy treats them as unsanctioned |
| Image-build or golden-image hosts | Low | `NOT Processes.dest IN ("vdi-gold-*")` in `..._filter` |
| The same score on the system as on the user | By design | If the host should score lower, edit `..._risk_score` (remove `risk_score` to fall back to the literal 20/20) |

---

## Response Actions

### If confirmed True Positive

1. **Contain:** uninstall the application through EDR, MDM or IT. For agentic browsers, sign out of the provider and revoke sessions the agent could reuse (SSO, SaaS tokens).
2. **Notify:** the user's manager, the endpoint owner and the AI governance owner.
3. **Investigate:** check uploads to the same provider in web, DLP or CASB data. Review what the agentic tool could reach. For an embedded Agent SDK, identify the vendor application and its data access.
4. **Remediate:** move the user to the sanctioned tool. Add application-control or MDM restrictions if policy requires them.
5. **Document:** record the tool, path, user, host and decision in the case.

### If Benign True Positive

1. Add the approval to `ai_sanctioned_entities` with an `expires` date. Provider strings emitted by this rule: `OpenAI`, `Anthropic`, `Cursor`, `Windsurf`, `ByteDance`, `Amazon`, `Perplexity`, `Pieces`, `Msty`, `AnythingLLM`.
2. Close the parent aggregator notable as Benign True Positive, with the reference to the approval.

## Tuning Guidance

### Reducing false positives

- Use `ai_sanctioned_entities`, not the filter macro, for sanctioned tools. Entries can expire.
- Add new apps in two places: the executable (and its `<app> helper*` form) in `_process_names`, and a branch in `_signature`. Keep the drilldown's inline name list in step.
- Do not add the Codex desktop app (`codex`) without path corroboration. AI-004 already scores the Codex CLI, and both share the executable name.

### Adjusting thresholds

There is no numeric threshold. Inventory over 7 days before enabling:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count dc(Processes.dest) as hosts dc(Processes.user) as users
    from datamodel=Endpoint.Processes
    where Processes.process_name IN (`hdsi_ai_unsanctioned_desktop_app_execution_process_names`)
    by Processes.process_name Processes.process_path
| rename Processes.* as *
| eval path_lc=lower(process_path), process_name_lc=lower(process_name)
| `hdsi_ai_unsanctioned_desktop_app_execution_signature`
| eval ide_hosted=if(`hdsi_ai_unsanctioned_desktop_app_execution_ide_host_exclusion`,1,0)
| stats sum(count) as events sum(hosts) as hosts sum(users) as users by tool provider app_class ide_hosted
| sort - hosts
```

`hosts` and `users` are summed per path, so they are upper bounds.

### Adding allowlist entries

```
entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
group,engineering,Cursor,provider,2027-03-31,secops,Cursor licence for engineering,1,engineering|cursor
user,jdoe@example.com,OpenAI,provider,2027-03-31,secops,ChatGPT desktop pilot,1,jdoe@example.com|openai
system,MAC-DESIGN-07,*,global,2027-03-31,it,Design lab AI tools,1,mac-design-07|*
```

Identities with no `bunit` can be allowlisted only by user or host.

## Data Requirements

| Requirement | Details |
|---|---|
| Data Model | `Endpoint.Processes`, accelerated (`summariesonly=t`) |
| Required Fields | `process_name`, `dest`. `process_path` is needed for `claude`, `trae`, `kiro` and `comet` (path-less inventory sources such as `WinHostMon` are dropped for these). Optional: `user`, `process`, `parent_process_name` |
| Sourcetype Examples | Windows 4688 or Sysmon EID 1 with image path, EDR process telemetry (including macOS) |
| CIM Compliance | Coverage must include **workstations**. Server-only telemetry or EDR event-stream feeds (only processes attached to an EDR event) give sparse coverage |
| Acceleration | Required |
| Lookups | Common: `ai_sanctioned_entities`, `ai_department_sensitivity`. ES: `identity_lookup_expanded` (`bunit`). The app catalogue is package-local (macros), not `ai_tool_processes` |
| Macros | Common: `ai_unsanctioned_filter(3)`, `ai_risk_multiplier`. Package: `hdsi_ai_unsanctioned_desktop_app_execution_*` |

### Validation summary (read-only live tests, 2026-10-09, 4 production ES tenants)

| Tenant | Endpoint.Processes | Parses (search + 2 drilldowns) | Before (4 h / 30 d) | After (4 h / 30 d) | Notes |
|---|---|---|---|---|---|
| A | about 174M a day, Windows 4688 with path | OK | 0 / 0 | 0 / 0 | No AI desktop executables in 30 days |
| B | about 51k a day: two servers plus EDR event-stream workstation data | OK | 0 / 0 | 0 / 1 | A Perplexity Comet session on macOS, seen only as `Comet Helper` (agentic, score 25). Missed before the helper fix |
| C | about 156M a day, about half path-less inventory | OK | 0 / 0 | 0 / 0 | Only the VS Code Copilot agent host's `claude.exe` and `codex.exe`, correctly excluded |
| D | about 210k a day | OK | 0 / 0 | 0 / 0 | No matching activity |

A synthetic positive test (11 rows, real identity, allowlist and multiplier lookups) returned exactly the 6 expected rows on all four tenants. On Tenant B, DNS showed much broader Claude, ChatGPT and Cursor desktop traffic than its process data can see. Pair this rule with the DNS and web rules.
