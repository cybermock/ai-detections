# AI-025 - Copy-Paste Correlation To AI Service

> **AD HOC PACKAGE.** `deployment_type: adhoc`. This rule needs paste telemetry that records the destination: Island Enterprise Browser / browser-extension audit logs (`sourcetype="island-audits"`) or a CIM `DLP` feed with paste/clipboard incidents that name the destination site. Only 1 of the 4 validation tenants had such a source (Island), and none had DLP data. Deploy it only where one of the `data_prereqs` searches in `package.yml` returns data.

> **Detection ID:** AI-025 (package `hdsi_ai_copy_paste_correlation_to_ai_service`, `detection_id="hdsi_ai_copy_paste_correlation_to_ai_service"`)
> **Search name:** `Endpoint - HDSI AI Copy-Paste Correlation To AI Service - Rule`
> **Status:** Active, ad hoc (ships with `enable_alerting: false`)
> **Output:** Risk only (`action.notable = 0`). Notables come from the `Threat - HDSI RBA AI ...` aggregators
> **Risk Score:** Dynamic on `user` and, when the source records a device hostname, `src` (system): base 20 (30 at 3x the paste threshold), +10 if any paste came from a business application or from outside the browser, x provider `severity_weight` x `risk_multiplier`, x0.5 when every paste was blocked; floored at 5, capped at 60. Literal `_risk` fallback user 20 / system 10
> **MITRE ATT&CK:** T1567 - Exfiltration Over Web Service (Exfiltration); T1115 - Clipboard Data (Collection)
> **Data Model:** Raw Island audit events (`island-audits`) and/or `DLP.DLP_Incidents`
> **Schedule:** `22 * * * *` (hourly at :22)
> **Lookback Window:** `-80m@m` to `-20m@m` (shifted 20 minutes for ingestion lag); suppression 24 h (`86400s`) per `user,src`
> **Kill Chain Phase:** `ai_kill_chain_phase="collection"`
> **Last Updated:** 2026-10-09

## Overview

This detection fires when a user **pastes or drags content into an AI service page 3 or more times in one hour** (per provider, by default). Pasting is the main way business text reaches ChatGPT, Gemini, Claude and similar tools, and proxy logs cannot see it. The rule uses telemetry that records the paste itself, its destination and, where available, where the content was copied from: Island `Paste`/`Drop` audit events, or CIM DLP clipboard incidents with a destination.

Pastes copied from business applications (SharePoint, Google Docs, Salesforce, ServiceNow and similar) or from outside the browser (a desktop application) score higher. The rule does not see what was pasted. It is a collection-phase signal: `Threat - HDSI RBA AI Data Collection Kill Chain - Rule` raises a notable when it is followed by an AI upload or exfiltration detection for the same user, and it counts in the `data_exposure` vector of the multi-vector aggregator.

The previous version paired any DLP copy/paste/cut event with any AI web traffic from the same user and read a non-existent `Data_Loss_Prevention` model (FATAL in every tenant). It was replaced by recorded pastes with their destination.

## Detection Logic

### Plain English

1. **Browser branch:** raw search `..._paste_events` (Island events containing `Paste` or `Drop`) plus the inline `..._filter`. `..._normalise` keeps `type` Paste/Drop and maps user, device hostname, the page pasted into, the tab copied from, and whether the content came from outside the browser. Island IP fields are never used (home-LAN or shared egress addresses).
2. **DLP branch (`append`):** `tstats` over `DLP.DLP_Incidents` for paste/clipboard incidents (`..._dlp_paste_events`, `..._dlp_filter`).
3. The paste destination is resolved with the common `ai_domains_filter` (`ai_input_type="host"`); non-AI destinations are dropped. Placeholder users/devices and IP-shaped `src` values become null; a row needs a user or a device.
4. Address Bar / Find Bar pastes are dropped. Pastes copied inside the same AI service are dropped (copy-source host equals or is a subdomain of the destination, or resolves to the same provider). Cross-application pastes inside one vendor (Gmail or Docs into Gemini, Outlook into M365 Copilot) are kept.
5. Each paste gets a copy-source class: `business_app` (matches `..._sensitive_copy_sources`), `other_site`, `outside_browser`, `not_recorded`.
6. Pastes are summed per `user`, `src`, `provider` over the hour; the rule keeps rows with `paste_count >= ..._min_pastes` (3), then applies `ai_unsanctioned_filter(user,src,provider)` and `ai_risk_multiplier`, then scores.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `user` | Island user (or email) / DLP user | `jdoe@example.com` |
| `src` | Device hostname, when recorded (empty with the Island browser extension) | `ws-0142` |
| `user_display`, `src_display` | Readable values; `src_display` reads "an unidentified device" when empty | `an unidentified device` |
| `provider`, `ai_domain_list` | AI provider and pasted-into hosts | `OpenAI`, `chatgpt.com` |
| `paste_count`, `blocked_count` | Pastes in the hour and how many were blocked | `7`, `0` |
| `copy_source_list`, `copy_source_class_list` | Where the content was copied from | `example.sharepoint.com`, `business_app` |
| `paste_verdict_list`, `paste_product` | Vendor verdicts and product | `allowed`, `Island Enterprise Browser` |
| `min_pastes`, `base_score`, `severity_weight`, `risk_multiplier`, `risk_score` | Scoring inputs and result | `3`, `30`, `1.0`, `1.0`, `30` |

### Thresholds

| Parameter | Default Value | Macro | Notes |
|---|---|---|---|
| Pastes per user, provider and hour | `3` | `hdsi_ai_copy_paste_correlation_to_ai_service_min_pastes` | Validation tenant (7 d): median 1, p90 5, p99 about 21 per user-hour |
| Business copy sources | regex of common business SaaS | `..._sensitive_copy_sources` | +10 points. Add the tenant's EHR, ERP, CRM, wiki and internal app domains |
| Island base search | `index=* sourcetype="island-audits"` | `..._paste_events` | Set the Island index for speed |

## Triage Steps

> **Estimated triage time:** 10 minutes. Replace `<user>`, `<src>` and `<provider>` with the risk event values. Run Step 3 over the rule's window or a few hours around it.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Endpoint - HDSI AI Copy-Paste Correlation To AI Service - Rule" risk_object="<user>"
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- The message lists the provider, paste count, copy sources with their class, and the verdicts.
- `business_app` or `outside_browser` in the class list is what raises the score.

### Step 2: Identify the user

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy priority bunit category
```

- Note the business unit: it drives `risk_multiplier` and group approvals.
- With the Island browser extension the device hostname is usually empty, so only the user carries risk.

### Step 3: Review the paste events

Browser pastes (same as the rule's second drilldown):

```spl
`hdsi_ai_copy_paste_correlation_to_ai_service_paste_events` user="<user>"
| `hdsi_ai_copy_paste_correlation_to_ai_service_normalise`
| eval ai_domain=paste_url, ai_input_type="host"
| `ai_domains_filter`
| table _time user src paste_type provider ai_domain copy_source_url copy_external paste_element paste_verdict paste_product
| sort - _time
```

DLP clipboard incidents:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime from datamodel=DLP.DLP_Incidents where `hdsi_ai_copy_paste_correlation_to_ai_service_dlp_paste_events` DLP_Incidents.user="<user>" by DLP_Incidents.user DLP_Incidents.src DLP_Incidents.dest DLP_Incidents.object_path DLP_Incidents.action DLP_Incidents.signature DLP_Incidents.vendor_product
| rename DLP_Incidents.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

- Look at the copy sources: an internal application, CRM, EHR, finance system or code repository is more serious than a course site or public web page.
- `copy_external=1` means the content came from a desktop application (Office, an IDE, a terminal).
- Keep the browser search filtered on `user`: wildcarding the user took about 220 s on the validation tenant. Set the Island index in `..._paste_events` for speed.

### Step 4: Check for related detections

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object="<user>" source="*HDSI AI*"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources by risk_object risk_object_type
| sort - total_risk
```

- Run over `-24h`. A collection detection followed by `Network - HDSI AI High Volume Upload To AI Service - Rule`, `Audit - HDSI AI DLP Violation On Service Upload - Rule` (incubating, not released) or `Network - HDSI AI Gradual Data Exfiltration Via AI - Rule` is what the data-collection kill-chain aggregator looks for.
- User thresholds: medium 60, critical 90 in a rolling 24 h.

### Step 5: Determine sanctioned status

```spl
| inputlookup ai_sanctioned_entities
| eval allow_key=lower(allow_key)
| search allow_key IN ("<user>|<provider>", "<user>|*", "<bunit>|<provider>", "*|<provider>")
| table entity_type entity provider scope expires owner reason enabled allow_key
```

- Use the lower-cased provider (`openai`, `google gemini`, `anthropic`, `perplexity`...). An enterprise AI tenant (for example an approved ChatGPT Enterprise workspace) belongs here, not in the filter macro.

### Step 6: Make a determination

- **True Positive:** repeated pastes of business-application content into an unsanctioned AI service, especially from regulated systems.
- **Benign True Positive:** pasting into an approved AI service, or ordinary pasting of public content (learning sites, general web pages).
- **False Positive:** the destination is not an AI service or the same-site logic missed a provider-internal copy (report it for tuning).

---

## True Positive Indicators

- Copy sources include internal applications, CRM/ERP/EHR, source repositories or document stores (`business_app`), or many `outside_browser` pastes.
- High `paste_count` (3x the threshold or more) in a single hour.
- The user's role handles regulated data (`risk_multiplier` > 1).
- The provider is not approved for the user's business unit.
- An upload or exfiltration detection follows for the same user (kill-chain aggregator notable).

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Ordinary AI use: pasting public content, coursework or general web pages (common copy sources in validation) | High | Scores stay modest (20-40 before multipliers); extend `..._sensitive_copy_sources` so business-data pastes stand out; approve sanctioned tools |
| Sanctioned enterprise AI tool used as intended | Medium | Add `<bunit>|<provider>` or `<user>|<provider>` approvals in `ai_sanctioned_entities` |
| Paste blocked by Island policy | Medium | Still scored at half weight; review whether the policy is doing its job |
| Pasting split across two scheduled hours is counted separately in each | Low | Expected; lower `..._min_pastes` only if the tenant profile supports it |
| Late events (about 1 in 20 arrived more than 11 minutes late; max about 2.8 h) fall outside the window | Low (missed detections, not false positives) | Widen the window shift if the feed is slower |

## Response Actions

### If confirmed True Positive

1. **Contain:** apply an Island (or browser DLP) policy that blocks or warns on paste into the unsanctioned provider for the user or group.
2. **Notify:** the user's manager and the data governance / privacy team.
3. **Investigate:** identify the copy-source applications and the data they hold; check Island's own DLP verdicts or session recording, if licensed, for content; check for later uploads to the same provider.
4. **Remediate:** point the user to the approved AI tool, request deletion of the conversation history at the provider where possible, and add content-aware paste controls.
5. **Document:** record findings in the case management system.

### If Benign True Positive

1. Add an approval to `ai_sanctioned_entities` with an `expires` date.
2. Document the business justification in the `reason` field.
3. Close the investigation as "Benign True Positive."

## Tuning Guidance

### Reducing false positives

- Set the Island index in `..._paste_events` before anything else.
- Add the tenant's own application domains to `..._sensitive_copy_sources`. Google Workspace tenants should add `mail\\.google\\.com` and `chat\\.google\\.com` (not shipped, because they share hosts with personal accounts).
- Exclude kiosk or service users with `..._filter` (raw Island field names), for example `NOT user IN ("svc_*")`.

### Adjusting thresholds

Profile 7 days and keep the threshold near `max(3, p90)`. If the 7-day search auto-finalises, run it in 1-day slices:

```spl
`hdsi_ai_copy_paste_correlation_to_ai_service_paste_events` earliest=-7d@h latest=@h
| `hdsi_ai_copy_paste_correlation_to_ai_service_normalise`
| eval ai_domain=paste_url, ai_input_type="host"
| `ai_domains_filter`
| where NOT match(lower(coalesce(paste_element,"")),"address bar|find bar")
| eval copy_source_domain=replace(lower(replace(replace(copy_source_url,"^[a-z][a-z0-9+.-]*://",""),"[/:?#].*$","")),"^www\\d*\\.","")
| where isnull(copy_source_domain) OR (copy_source_domain!=ai_domain AND NOT like(copy_source_domain,"%.".ai_domain))
| bin _time span=1h
| stats count by _time user provider
| stats count as user_hours dc(user) as users perc50(count) as p50 perc90(count) as p90 perc99(count) as p99 max(count) as max count(eval(count>=3)) as hours_ge3
```

### Adding allowlist entries

```
entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
group,marketing,OpenAI,group,2026-12-31,security,approved_chatgpt_enterprise,1,marketing|openai
user,jdoe@example.com,Google Gemini,provider,2026-12-31,security,approved_gemini_pilot,1,jdoe@example.com|google gemini
```

A group key matches the user's ES identity `bunit`, so it works only for users present in `identity_lookup_expanded`.
