# AI-045 - Voice Cloning API Access

> **Detection ID:** AI-045
> **Package:** `hdsi_ai_voice_cloning_api_access` v1.1.0 (`deployment_type: global`, ships `enable_alerting: false`)
> **Search name:** `Threat - HDSI AI Voice Cloning API Access - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`, severity low). Notables come from the HDSI RBA AI aggregators
> **Risk objects:** `user` (user) and/or `src` (system). The same computed score applies to both
> **Risk score:** dynamic, `min(60, max(3, round(base_score x risk_multiplier)))`. Base 8-35 by evidence class x provider `severity_weight`, +5 per extra provider, +15 for an upload of 1 MB or more to voice-clone routes. Literal fallback 20 / 20
> **MITRE ATT&CK:** T1588.007 Obtain Capabilities: Artificial Intelligence (Resource Development)
> **Data Model:** `Web` (egress proxy, firewall URL or SSE logs) and/or `Network_Resolution` (DNS)
> **Schedule:** `53 1 * * *` (daily at 01:53)
> **Lookback Window:** `-1d@d` to `@d` (yesterday)
> **Suppression:** 23 hours per `user,src` (`82800s`)
> **Kill Chain Phase:** `staging`
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds **users and hosts that use hosted voice cloning and voice conversion services**: ElevenLabs, PlayHT, Resemble AI, WellSaid Labs, Murf AI, LOVO AI, Coqui, FakeYou, Uberduck, Voicemod, HeyGen, Fish Audio and Cartesia. A cloned voice is the raw material for CEO-voice fraud, vishing and fake help-desk calls. The same services are also bought for narration, e-learning and accessibility, so using one is a **context signal, not an incident**.

Evidence comes from Web (proxy, firewall URL or SSE logs) and DNS. Each request is classified by host and path. In-app voice cloning or conversion requests score highest; Voice Lab and voice design come next, then repeated signed-in app use. API use, site plus API use and repeated marketing or product page visits score low. Docs, help, blog and pricing pages, sign-up and sign-in pages, embedded players and voice-agent widgets (on decrypted URLs), and single visits do not qualify. The rule runs once a day, writes risk between 3 and 60 on the user and/or host, and never raises a notable.

## Detection Logic

### Plain English

1. **Collect** (yesterday): `Web` pre-filtered by `..._web_scope` (provider domains and SSE app names), split by `sourcetype`, `user`, `src`, `url_domain`, `site` and `url`; an appended `Network_Resolution` search pre-filtered by `..._dns_scope`, counted in **lookup-minutes** (distinct minutes in which a client looked a name up); and a shared-source guard listing DNS clients that resolved at least `..._shared_src_names` (10,000) distinct names (resolvers, forwarders, NAT egress).
2. **Resolve** the provider with `ai_domains_filter` (`url_domain`, else `site`, else the DNS query) and keep only `..._providers`. Placeholder users are dropped. Public source addresses, shared DNS clients and `..._untrusted_src` addresses are never used as the `src` risk object.
3. **Classify each request** by `class_host` (the host from `Web.url` when present) and `url_path`; first match wins, background is checked first:
   - **background** (never counted): embedded players and voice-agent widgets, share/embed links, affiliate links, docs, help, blog, pricing, static assets, CDNs, analytics.
   - **clone** (35): `/v1/voices/add`, `/v1/voices/pvc`, `/v1/speech-to-speech`, PlayHT `/api/v2/cloned-voices`, clone/voice-changer/speech-to-speech pages inside `/app/` or `/studio/` or on an app host.
   - **voicelab** (25): `/app/voice-lab`, `/app/voice-design`, `/v1/text-to-voice`, `/v1/voice-generation`.
   - **app** (20, needs `..._min_app_events` = 2): app and studio hosts, `/app/`, `/studio/`, `/dashboard/` paths, minus account pages.
   - **api** (12): provider API hosts, at `..._min_api_events` (10) alone, or with site requests totalling `..._min_browse_events` (5).
   - **browse** (8, needs 5): any other provider page, including product pages such as `/voice-cloning`.
4. **Attribute:** DNS rows from a host with exactly one Web user that day are attributed to that user. The entity is the user when known, otherwise the host.
5. **Approvals:** `ai_unsanctioned_filter(user,src,provider)` removes user, host, `bunit` (identity, else asset) or organisation-wide (`*|<provider>`) approvals.
6. **Score:** provider score = base x `severity_weight` (x0.5 if every request was blocked); entity `base_score` = highest provider score + 5 per extra provider + 15 if at least `..._upload_mb` (1 MB) was sent to clone routes; then x `risk_multiplier`, between 3 and 60.

## Triage Steps

> **Estimated triage time:** 10-20 minutes

Replace `$risk_object$` with the risk object, `$risk_entity$` with the finding's `risk_entity`, and `$src_hosts$` with its `src_hosts` (comma-separated). Set the time picker to the evaluated day unless noted.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Threat - HDSI AI Voice Cloning API Access - Rule" risk_object="$risk_object$"
| table _time, risk_object, risk_object_type, risk_score, risk_message
| sort - _time
```

Set the time picker to 30 days.

- Read `evidence_list`: `voice cloning or conversion request` (35) and `Voice Lab or voice design use` (25) are the strong classes; `sustained API use`, `site and API use` (12) and `repeated site visits` (8) are weak.
- An "about N MB sent to voice-clone routes" phrase means audio was uploaded to a clone route.
- System-only risk (no user) comes from DNS or from firewall URL rows without User-ID; it is low-weight context.

### Step 2: Review the web activity

Drilldown 2. `url_domain` falls back to `site` for SSE app names:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count sum(Web.bytes_out) as bytes_out sum(Web.bytes_in) as bytes_in values(Web.action) as action values(Web.http_method) as http_method min(_time) as firstTime max(_time) as lastTime
    from datamodel=Web
    where (Web.user="$risk_entity$" OR Web.src="$risk_entity$") `hdsi_ai_voice_cloning_api_access_web_scope`
    by sourcetype Web.user Web.src Web.url_domain Web.site Web.url
| rename Web.* as *
| eval url_domain=if(url_domain="unknown",site,url_domain), mb_out=round(bytes_out/1048576,2), mb_in=round(bytes_in/1048576,2)
| convert ctime(firstTime) ctime(lastTime)
| table firstTime, lastTime, user, src, url_domain, url, action, http_method, count, mb_out, mb_in, sourcetype
| sort - count
```

- Clone routes (`/v1/voices/add`, `/v1/speech-to-speech`, `/cloned-voices`, `/app/.../speech-to-speech`) are the decisive evidence. Voice Lab pages are where clones are created, but also where stock voices are picked.
- Host-only rows (no path) to `api.<provider>` in a short burst are usually an embedded player or voice-agent widget on another website.
- For Netskope sourcetypes, `bytes_out` holds server-to-client bytes; the upload is `bytes_in`.

### Step 3: Review the DNS lookups

Drilldown 3:

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime
    from datamodel=Network_Resolution
    where `hdsi_ai_voice_cloning_api_access_dns_scope`
    by DNS.src DNS.query sourcetype
| rename DNS.* as *
| search src IN ($src_hosts$)
| convert ctime(firstTime) ctime(lastTime)
| table firstTime, lastTime, src, query, count, sourcetype
| sort - count
```

- Studio or app hosts (`studio.`, `app.`, `genny.`) looked up in several distinct minutes indicate signed-in use. A single minute with app, API and site lookups is one visit.
- If `src_hosts` is `none`, the finding is user-only Web evidence.

### Step 4: Identify the user or host

```spl
| inputlookup identity_lookup_expanded
| search identity="$risk_entity$" OR email="$risk_entity$"
| table identity, first, last, email, bunit, category, priority, managedBy
```

```spl
| inputlookup asset_lookup_by_str
| search ip="$risk_entity$" OR dns="$risk_entity$" OR nt_host="$risk_entity$"
| table ip, dns, nt_host, owner, bunit, category, priority
```

- Is the user in marketing, training, communications or accessibility services (likely licensed use)?
- Or in finance, executive support or the help desk, or an executive assistant (higher concern for impersonation)?

### Step 5: Check for impersonation-related activity

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object="$risk_object$" source="*HDSI AI*"
| stats count as events, sum(risk_score) as total_risk, dc(source) as detections, values(source) as sources by risk_object, risk_object_type
```

Run over 7 days.

- AI-034 (Deepfake Tool Execution/Access) or AI-031 (AI-Generated Phishing Indicators) for the same user or host is a strong escalation signal; together they put the person in the `adversarial` vector of AI-RISK-005.
- Check recent vishing or help-desk social-engineering reports for voices of executives or staff in the user's area.

### Step 6: Determine sanctioned status

```spl
| inputlookup ai_sanctioned_entities
| search enabled=1 (entity="$risk_entity$" OR entity="*")
| table entity_type, entity, provider, scope, expires, owner, reason, allow_key
```

- Keys: `<user, src or bunit>|<provider>` (e.g. `training|wellsaid labs`), `<entity>|*`, or `*|<provider>` for an organisation-wide licence. Provider names are the ones in `..._providers`, lowercased.

### Step 7: Make a determination

- **True Positive:** clone or voice-conversion requests (or an upload to a clone route) by a user with no business need, especially with deepfake, phishing or impersonation context.
- **Benign True Positive:** licensed narration, training or accessibility use. Approve the user, `bunit` or provider.
- **False Positive:** an embedded player or voice-agent widget seen on host-only logs, or a browser extension, scored as API or site use.

## True Positive Indicators

- `clone_events` > 0, or an upload of 1 MB or more to clone routes (about one minute of speech, enough for an instant clone).
- Voice Lab use followed by speech-to-speech or voice-changer requests.
- The user has no media, training or accessibility role, or works close to executives, finance or the help desk.
- Co-occurring deepfake, phishing or lateral-movement AI detections.
- Use of consumer voice-changer services (Voicemod, FakeYou, Uberduck) from corporate hosts.

## False Positive Scenarios

Evidence from read-only validation on 4 production ES tenants (Tenant A-D), 2026-10-09.

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Licensed narration and training content (on Tenant C every qualifying row was WellSaid Labs studio use) | High where licensed | Approve by `bunit`, user, or `*|<provider>` |
| Embedded voice agents and audio players on host-only (SNI) logs: on Tenant A most rows on the busiest days were host-only `api.elevenlabs.io` traffic of 10-19 requests in a 1-2 hour burst | Medium | They score 12 (6 when blocked); list VPN or guest ranges in `..._untrusted_src` if host risk there is not useful |
| Voice Lab used to pick stock voices (the only cloning-related path seen in validation: one Tenant A user with 17 Voice Lab requests scored 23) | Medium | Scores 25 x weight, not 35; confirm with Step 2 |
| Marketing or product pages (`/voice-cloning`, `/voice-changer`) visited 5+ times | Low | Score 8; docs, help, blog and pricing pages never count |
| Single visits (a HeyGen visit on Tenant B with 1 app, 1 API and 3 site lookups in one minute) | Low after v1.1 | Dropped by the 2-app-request rule |
| Providers out of scope by design: Deepgram (about 15,000 requests from 31 users in 7 days on Tenant A, speech-to-text in dictation tools), Speechify (reading extension), Synthesia (173 hosts a week on Tenant B), Descript | n/a | Deliberately absent from `..._providers`; add back only as a deliberate choice |

## Response Actions

### If confirmed True Positive

1. **Contain:** block the voice cloning provider for the user or host (proxy/SSE or DNS policy). If clone uploads occurred, preserve the proxy/SSE logs and any endpoint audio files.
2. **Notify:** the security incident lead and, if a specific person's voice may have been cloned (an executive, a manager, a help-desk agent), that person and the teams they work with. Warn finance and the help desk to verify voice requests out of band.
3. **Investigate:** determine whose voice was used (endpoint audio files, meeting recordings accessed, the account on the provider), and correlate with phishing, vishing or payment-change reports.
4. **Remediate:** request deletion of the cloned voice from the provider where possible; reinforce call-back verification procedures for payments and credential resets.
5. **Document:** record provider, evidence class, uploads, involved identities and disposition.

### If Benign True Positive

1. Add the approval to `ai_sanctioned_entities` (`<bunit>|wellsaid labs`, `<user>|elevenlabs`, or `*|wellsaid labs` for an organisation-wide licence) with an expiry and reason.
2. Close the aggregator notable (if any) as benign.

## Tuning Guidance

### Reducing false positives

- Load approvals for licensed voice and narration services first; on the SSE validation tenant this removes almost all findings.
- Add resolvers or forwarders that resolve fewer than 10,000 names a day to `hdsi_ai_voice_cloning_api_access_dns_filter`; add VPN or guest pools to `..._untrusted_src` (e.g. `cidrmatch("100.64.0.0/10",src)`).
- Check byte direction for each byte-carrying sourcetype and keep `..._bytes_reversed` correct (on Tenant C, Netskope `bytes_out` was about 4.4x `bytes_in` across all traffic):

```spl
| tstats summariesonly=t allow_old_summaries=t sum(Web.bytes_out) as bytes_out sum(Web.bytes_in) as bytes_in from datamodel=Web by sourcetype
| where bytes_in>0
| eval out_in_ratio=round(bytes_out/bytes_in,2)
| sort - out_in_ratio
```

- Override the score in `hdsi_ai_voice_cloning_api_access_risk_score` (last pipe, 1-100; it applies to both risk objects).

### Adjusting thresholds

Find resolvers and shared egress addresses for the shared-source guard (run over one full day):

```spl
| tstats summariesonly=t allow_old_summaries=t dc(DNS.query) as names from datamodel=Network_Resolution by DNS.src
| where names>=3000
| sort - names
```

In validation ordinary clients resolved fewer than about 3,000 distinct names a day; resolvers and egress addresses 11,000-380,000. The README Threshold section has the SPL that derives `..._min_api_events` from a week of API-only entity-days (Tenant A: p50 1, p90 about 10, p99 about 64).

### Adding providers

The provider must exist in `ai_provider_domains` or `ai_provider_apps` (common package). Then add its name to `..._providers`, its domain to `..._web_scope` and `..._dns_scope`, and its SSE application name to `..._web_scope`.
