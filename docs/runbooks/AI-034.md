# AI-034 - Deepfake Tool Execution/Access

> **Detection ID:** AI-034 (package `hdsi_ai_deepfake_tool_execution_access`, `detection_id="hdsi_ai_deepfake_tool_execution_access"`)
> **Search name:** `Endpoint - HDSI AI Deepfake Tool Execution/Access - Rule`
> **Status:** Active, `deployment_type: global` (ships with `enable_alerting: false`)
> **Output:** Risk only (`action.notable = 0`). Notables come from the `Threat - HDSI RBA AI ...` aggregators
> **Risk Score:** Dynamic on `user` and `src` (system): `risk_score = min(80, round(base_score x risk_multiplier))`, base 40 (face swap or voice clone), 30 (lip sync / talking head), 15 (local image generation only). Literal `_risk` fallback 40 / 40
> **MITRE ATT&CK:** T1588.007 - Obtain Capabilities: Artificial Intelligence (Resource Development)
> **Data Model:** `Endpoint.Processes`
> **Schedule:** `4-59/15 * * * *` (every 15 minutes)
> **Lookback Window:** `-20m@m` to `-5m@m`; suppression 24 h (`86400s`) per `user,src`
> **Kill Chain Phase:** `ai_kill_chain_phase="staging"`
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds endpoints running **open-source deepfake and synthetic-media tooling**: face swap (FaceFusion, Deep-Live-Cam, DeepFaceLab, DeepFaceLive, Roop and its forks, Rope/VisoMaster, ReActor, Faceswap, SimSwap, Avatarify), voice cloning (RVC/Applio, Coqui XTTS, Tortoise TTS, OpenVoice, GPT-SoVITS/So-VITS-SVC, Fish Speech, CosyVoice, StyleTTS, F5-TTS, WhisperSpeech, VALL-E-X), lip sync and talking-head generation (Wav2Lip, SadTalker, LivePortrait, MuseTalk, LatentSync), and local image generation (Stable Diffusion WebUI, ComfyUI, Fooocus). It also catches acquisition, such as `git clone` of a tool repository.

These tools are what an insider or intruder needs to stage CEO-voice fraud, fake video calls or synthetic identity documents, and they have almost no legitimate use on a corporate workstation. Local image generators are the exception (design and marketing teams), so they score lowest.

The rule raises risk on the user and the host and creates no notable. It counts in the `adversarial` (high-impact) vector of `Threat - HDSI RBA AI Multi-Vector Risk - Rule`. Hosted deepfake SaaS (ElevenLabs, PlayHT, Resemble AI) is out of scope here and is covered by `Threat - HDSI AI Voice Cloning API Access - Rule`.

## Detection Logic

### Plain English

1. `tstats` (`fillnull_value="unknown"`) over `Endpoint.Processes`, pre-filtered inline by `..._tool_terms` (substrings of tool repository, script, model and process names, plus tool-specific arguments such as `--frame-processor`, `face_swapper`, `run.py --execution-provider` and `--driven_audio`) and `..._filter`. `fillnull_value` keeps sources that have a command line but no `process_path`.
2. `..._classify` assigns `tool_name` and `tool_category` with boundary-anchored regexes. It first masks the user-profile folder name (so a profile such as `C:\Users\roop.example\` cannot match) and removes URLs from browser, `explorer.exe` and `rundll32.exe` command lines (a clicked link is not execution; `git`, `curl`, `pip` and PowerShell downloads keep their URLs). Rows with no tool are dropped.
3. Machine accounts (`*$`), `SYSTEM`, `LOCAL SERVICE`, `NETWORK SERVICE` and `unknown` users are cleared, so only the host is scored for those rows. Rows with neither user nor host are dropped.
4. Results are aggregated per `user` + `src` with tools, categories, execution count and the earliest command line as `process_sample`.
5. `ai_unsanctioned_filter(user,src,provider)` with `provider="Deepfake Tool"` removes approved users, hosts and groups; `ai_risk_multiplier` adds `risk_multiplier`; the score is computed.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `user` | Account that ran the tool (null for system and machine accounts) | `jdoe@example.com` |
| `src` | Host (`Processes.dest`) | `ws-0142` |
| `user_display`, `host_display` | Readable values when one side is missing | `a system or unattributed account` |
| `tools` | Tool names matched | `Deep-Live-Cam` |
| `tool_categories` | `face_swap`, `voice_clone`, `lip_sync_avatar`, `image_generation` | `face_swap` |
| `executions` | Process events in the window | `4` |
| `process_sample` | Earliest command line (250 chars) | `python run.py --execution-provider cuda` |
| `process_name`, `parent_process_name`, `process` | Process details | `python.exe`, `cmd.exe` |
| `base_score`, `risk_multiplier`, `risk_score` | Scoring inputs and result | `40`, `1.0`, `40` |

### Thresholds

| Parameter | Default Value | Macro | Notes |
|---|---|---|---|
| Count threshold | none | n/a | A single execution is the signal; 24 h suppression bounds volume |
| Score cap | `80` | (in SPL) | Override in `hdsi_ai_deepfake_tool_execution_access_risk_score` |
| Tool terms / classifier | shipped lists | `..._tool_terms`, `..._classify` | Add a new tool to both macros together |

## Triage Steps

> **Estimated triage time:** 15 minutes. Replace `<user>` and `<src>` with the risk event values.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Endpoint - HDSI AI Deepfake Tool Execution/Access - Rule" (risk_object="<user>" OR risk_object="<src>")
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- The message names the tools, categories and a sample command line.
- A label of `Roop-family face swapper (generic launch)` means only the argument shape matched; verify it in Step 3.

### Step 2: Identify the user and host

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy priority bunit category
```

```spl
| inputlookup asset_lookup_by_str
| search ip="<src>" OR dns="<src>" OR nt_host="<src>"
| table ip dns nt_host owner priority bunit category
```

- Is the user in a team with a legitimate synthetic-media need (marketing, media lab, research)?
- Does the user have access to executives, finance approvals or identity verification processes (fraud enablement)?

### Step 3: Review the process activity

Same as the rule's second drilldown (host **or** user, last 7 days):

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count min(_time) as firstTime max(_time) as lastTime values(Processes.parent_process_name) as parent_process_name values(Processes.process_path) as process_path from datamodel=Endpoint.Processes where earliest=-7d (Processes.dest="<src>" OR Processes.user="<user>") `hdsi_ai_deepfake_tool_execution_access_tool_terms` by Processes.user Processes.dest Processes.process_name Processes.process
| rename Processes.* as *
| `hdsi_ai_deepfake_tool_execution_access_classify`
| where isnotnull(tool_name)
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user dest tool_name tool_category process_name parent_process_name process_path process count
| sort - count
```

- Acquisition only (`git clone`, `pip install`, a download) versus actual runs (`python ... run.py`, `infer-web.py`, the tool's own executable).
- Input files in the command line: source faces, voice samples or video of identifiable people, especially executives.
- Generic `run.py --execution-provider` launches: confirm the folder or other arguments really belong to Roop or Deep-Live-Cam; other ONNX tools (for example a background remover) share this shape.
- A non-profile folder named exactly like a tool (for example a share folder `\\server\projects\roop\`) can still match.

### Step 4: Check for related detections

```spl
| from datamodel:"Risk.All_Risk"
| search (risk_object="<user>" OR risk_object="<src>") source="*HDSI AI*"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources by risk_object risk_object_type
| sort - total_risk
```

- Run over `-24h` and `-7d`. Look especially for `Threat - HDSI AI Voice Cloning API Access - Rule` (hosted voice cloning), `Threat - HDSI AI Generated Phishing Indicators - Rule` and `Network - HDSI AI LLM Model File Download - Rule`.
- User thresholds: medium 60, critical 90 in a rolling 24 h. One face-swap hit (40) plus a second detection reaches the medium band quickly.

### Step 5: Determine sanctioned status

```spl
| inputlookup ai_sanctioned_entities
| eval allow_key=lower(allow_key)
| search allow_key IN ("<user>|deepfake tool", "<user>|*", "<src>|deepfake tool", "<src>|*", "<bunit>|deepfake tool", "*|deepfake tool")
| table entity_type entity provider scope expires owner reason enabled allow_key
```

- The provider key for this rule is `deepfake tool`. Group keys match the user's ES identity `bunit` only for users in `identity_lookup_expanded`.

### Step 6: Make a determination

- **True Positive:** face-swap, voice-clone or lip-sync tooling run or acquired by a user with no approved purpose.
- **Benign True Positive:** an approved media, marketing or research team (allowlist it), or image generation by a design team.
- **False Positive:** a coincidental folder name, or a generic `run.py --execution-provider` launch of a non-deepfake tool.

---

## True Positive Indicators

- Face-swap or voice-clone tools (`base_score` 40) on a general business workstation.
- Input media of executives, colleagues or identity documents in the command line or nearby file activity.
- The tool runs shortly before payment, vendor-change or helpdesk identity-verification requests involving the same user.
- `git clone` or download of the tool followed by execution on the same host.
- Other HDSI AI adversarial detections (voice-cloning API access, AI-generated phishing) for the same user.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Design or marketing team running ComfyUI, Stable Diffusion WebUI or Fooocus | Medium | Scores 15. Allowlist the team (`<bunit>|deepfake tool`) or lower the image-generation score in `..._risk_score` |
| Approved media lab or AI research team | Low | `<bunit>|deepfake tool` or host approval with `expires`; or `..._filter` |
| Generic `python run.py --execution-provider` launch of another ONNX/insightface tool (for example a background remover) | Low | Exclude the known shape in `..._filter`, e.g. `NOT Processes.process="*--model rembg*"` |
| Non-profile folder named exactly like a tool (`\\server\projects\roop\`) | Low | Exclude the path in `..._filter` or allowlist the host |
| Substring noise (temp folders, Java classpaths, base64) | Very low | Already rejected by the boundary regexes (54 raw events on 17 hosts in 7 d on Tenant A, 0 classified). Do not loosen `..._classify` |

## Response Actions

### If confirmed True Positive

1. **Contain:** remove the tool and any generated media; isolate the host if the user's intent is malicious or the account may be compromised.
2. **Notify:** HR and legal (insider case), the user's manager, and finance / helpdesk teams if executive impersonation is possible.
3. **Investigate:** identify source media and outputs on disk, where outputs were sent (email, chat, cloud storage), and whether any call or payment request used synthetic media.
4. **Remediate:** strengthen out-of-band verification for payments and account recovery; block the tool's repositories and model downloads for non-approved groups.
5. **Document:** record findings in the case management system.

### If Benign True Positive

1. Add an approval to `ai_sanctioned_entities` (`<user or host>|deepfake tool`, or `<bunit>|deepfake tool`) with an `expires` date.
2. Document the business justification in the `reason` field.
3. Close the investigation as "Benign True Positive."

## Tuning Guidance

### Reducing false positives

- Allowlist approved synthetic-media teams rather than tolerating their events as noise.
- Never add a bare short word to `..._tool_terms`: a bare `*rope*` matched about 35M process events in 7 days on one tenant (`property`, `SystemPropertiesProtection.exe`).
- Use `..._customizations` for post-aggregation filtering, for example `search NOT (tool_categories="image_generation" AND src="design-*")`.

### Adjusting thresholds

There is no count threshold. Measure raw versus classified matches over 7 days before enabling:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count from datamodel=Endpoint.Processes where `hdsi_ai_deepfake_tool_execution_access_tool_terms` by Processes.user Processes.dest Processes.process_name Processes.process_path Processes.process
| rename Processes.* as *
| `hdsi_ai_deepfake_tool_execution_access_classify`
| fillnull value="(rejected noise)" tool_category
| stats sum(count) as raw_matches dc(dest) as hosts dc(user) as users sum(eval(if(isnotnull(tool_name),count,0))) as classified values(tool_name) as tools by tool_category
```

### Adding allowlist entries

```
entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
group,media-lab,Deepfake Tool,group,2026-12-31,security,approved_synthetic_media_lab,1,media-lab|deepfake tool
system,render-ws-01,Deepfake Tool,provider,2026-12-31,security,approved_render_host,1,render-ws-01|deepfake tool
```

`*|deepfake tool` (`entity_type=group`, `entity=*`, `scope=global`) switches the rule off organisation-wide without disabling it.
