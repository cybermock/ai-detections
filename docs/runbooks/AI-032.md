# AI-032 - Suspicious Model File Exfiltration

> **Detection ID:** AI-032
> **Package:** `hdsi_ai_suspicious_model_file_exfiltration` (v1.1.0, `deployment_type: global`)
> **Search name:** `Threat - HDSI AI Suspicious Model File Exfiltration - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`, `action.risk = 1`). The package ships with `enable_alerting: false`.
> **Risk Score:** Dynamic, 10-70 per event, applied to both risk objects (`user`, `src`). Literal fallback: user 40, system 30.
> **MITRE ATT&CK:** T1567.001 - Exfiltration to Code Repository; T1567.002 - Exfiltration to Cloud Storage (Exfiltration)
> **Data Model:** Web, Network_Traffic and Endpoint.Processes (any one is enough)
> **Schedule:** `23 * * * *` (hourly)
> **Lookback Window:** `-65m@m` to `-5m@m`
> **Suppression:** 24 hours per `user`,`src`
> **Kill Chain Phase:** `exfiltration` (RBA vector `data_exposure`; also an exfiltration step in the data-collection kill chain aggregator)
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds a user or host **publishing a model or dataset to an external model hub**: Hugging Face, ModelScope, the Ollama registry, Replicate's `r8.im` model registry or Kaggle. Proprietary model weights, fine-tuned adapters and training datasets are high-value intellectual property, and a model hub is a convenient, rarely blocked place to move them.

Evidence comes from any of three sources: a publish command on an endpoint, an upload-only API request or upload App-ID on the network, or a large upload volume to a model host. Downloading or browsing models never counts. Neither does inference traffic (chat, embeddings, predictions) wherever the source logs the request host or URL path. ML infrastructure is a +10 score modifier, not a gate.

Zero results is the expected steady state: no validation tenant published to a model hub during the validation week. Where an ML team publishes legitimately, expect about one risk event per publishing user and host per day until it is allow-listed. The rule creates no notable.

## Detection Logic

### Plain English

1. **Web branch.** `tstats` over `Web`, scoped to model-host domains and SSE app names (`..._web_scope`). A POST/PUT/PATCH whose path matches `..._upload_url_regex` is an upload-API request: Hugging Face Xet xorb/shard uploads, `preupload` and `xet-write-token` calls, Git LFS upload verify, OCI blob uploads and manifest pushes (Ollama, `r8.im`). Inference hosts and paths (`..._inference_regex`) are dropped first.
2. **Network_Traffic branch.** `tstats` over `Network_Traffic`, scoped to model-hub App-IDs (`..._traffic_scope`). The PAN `-base` suffix is stripped. `huggingface-upload` is upload evidence.
3. **Endpoint branch.** `tstats` over `Endpoint.Processes` with a broad command-line pre-filter (`..._process_scope`), confirmed by `..._upload_tool_regex`: `hf`/`huggingface-cli upload`, `ollama push`, `cog push`, Kaggle model-version and dataset uploads, `modelscope upload`, `git push` with a hub URL, the git-lfs `pre-push` hook for a hub remote, `--push_to_hub` training flags, `push_to_hub(` and `huggingface_hub`/`HfApi` upload calls. Tokens, passwords and URL credentials are masked before the command reaches the risk message.
4. All branches resolve the provider through the common `ai_domains_filter`. Only `model_registry` and `local_llm` rows are kept, so `api.replicate.com` and the Replicate App-IDs never count.
5. Clean identities. Placeholder, IP-shaped, `SYSTEM`, service and machine users become null. A public `src` (`..._untrusted_src`: public IPv4 or global-unicast IPv6) is never a risk object. Rows with no user and no trusted `src` are dropped, which removes inbound load-balancer and WAF logs.
6. Enrich with the ES identity `bunit` and the source asset's `bunit` and `category` (`asset_lookup_by_str` by `ip`, `dns`, then `nt_host`). Remove approved entities with `ai_unsanctioned_filter`.
7. Keep a row when at least one piece of evidence holds:
   - `publish command`: one command is enough;
   - `upload App-ID`: at least 10 MB (`..._min_evidence_mb`) sent with the upload App-ID;
   - `upload API request`: at least 10 MB sent, or the source does not log bytes;
   - `large upload`: at least 100 MB (`..._min_mb`) sent to model hosts in the hour.
8. Score and write risk.

### Risk scoring

| Step | Value |
|---|---|
| Base | 45 for a publish command; 40 for upload App-ID or upload API evidence; 35 for volume only |
| + 10 | More than one kind of evidence |
| + 10 | Source asset category matches `..._ml_asset_regex` (word-bounded ML, GPU, data-science, MLOps terms) |
| × `risk_multiplier` | Identity `bunit` sensitivity × 1.25 for privileged identities, capped at 2.0 |
| Clamp | `risk_score = min(70, max(10, round(...)))` |

ES applies the computed `risk_score` to every risk object in the row.

### Thresholds

| Parameter | Default Value | Macro | Notes |
|---|---|---|---|
| Volume on its own | 100 MB per user/host per hour | `hdsi_ai_suspicious_model_file_exfiltration_min_mb` | A small quantised model is hundreds of MB. Largest hourly upload seen in validation: about 1 MB (App-ID data) |
| Minimum MB for App-ID or upload-API evidence when bytes are logged | 10 MB | `hdsi_ai_suspicious_model_file_exfiltration_min_evidence_mb` | Keeps model-card and README edits (a few KB) out |

## Triage Steps

> **Estimated triage time:** 15-30 minutes

Replace `<user>`, `<src>` and `<risk_object>` with values from the risk event.

### Step 1: Read the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Threat - HDSI AI Suspicious Model File Exfiltration - Rule" risk_object="<risk_object>"
| table _time risk_object risk_object_type risk_score risk_message
| sort - _time
```

- The message lists the provider, the evidence kinds, MB sent, the hosts, and up to two publish commands with secrets masked.
- `publish command` evidence names the target repository (`hf upload <org>/<repo>`, `ollama push <namespace>/<model>`, `kaggle datasets create -p <dir>`). The organisation or namespace tells you whether it is the corporate account or a personal one.

### Step 2: Review the publish commands (endpoint evidence)

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime from datamodel=Endpoint.Processes where (Processes.user="<user>" OR Processes.dest="<src>") `hdsi_ai_suspicious_model_file_exfiltration_process_scope` by Processes.user Processes.dest Processes.parent_process_name Processes.process_name Processes.process
| rename Processes.* as *
| where match(process,`hdsi_ai_suspicious_model_file_exfiltration_upload_tool_regex`)
| sort - lastTime
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user dest parent_process_name process_name process count
```

- Note the repository ID, the local path (which model or dataset directory) and the parent (a person in a shell, a training job, a CI runner).
- This query shows command lines unmasked. Do not paste them into tickets without removing tokens. Any token on the command line must be rotated.

### Step 3: Review the network evidence

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count sum(Web.bytes_out) as bytes_out min(_time) as firstTime max(_time) as lastTime from datamodel=Web where (Web.user="<user>" OR Web.src="<src>") `hdsi_ai_suspicious_model_file_exfiltration_web_scope` by sourcetype Web.user Web.src Web.url_domain Web.site Web.http_method Web.url
| rename Web.* as *
| eval url_domain=if(url_domain="unknown",site,url_domain), mb_out=round(tonumber(bytes_out)/1048576,2)
| sort - mb_out
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user src url_domain http_method url count mb_out sourcetype
```

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="unknown" count sum(All_Traffic.bytes_out) as bytes_out sum(All_Traffic.bytes_in) as bytes_in values(All_Traffic.dest) as dest min(_time) as firstTime max(_time) as lastTime from datamodel=Network_Traffic where (All_Traffic.user="<user>" OR All_Traffic.src="<src>") `hdsi_ai_suspicious_model_file_exfiltration_traffic_scope` by sourcetype All_Traffic.user All_Traffic.src All_Traffic.app
| rename All_Traffic.* as *
| eval mb_out=round(bytes_out/1048576,2), mb_in=round(bytes_in/1048576,2)
| sort - mb_out
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user src app count mb_out mb_in dest sourcetype
```

- Upload paths (`/v1/xorbs`, `/preupload/`, `/v2/.../blobs/uploads/`) plus high `mb_out` confirm a real upload.
- `mb_in` much larger than `mb_out` is a download; a download alone never fires the rule.
- Extend the time range to 7 days to see whether this is a one-off or a recurring publishing job.

### Step 4: Identify the source asset and user

```spl
| inputlookup asset_lookup_by_str
| search ip="<src>" OR dns="<src>" OR nt_host="<src>"
| table ip dns nt_host owner bunit category priority
```

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy bunit category priority
```

- An ML or GPU server, a data-science workstation or a training cluster holds the material worth stealing. An ordinary laptop publishing hundreds of MB is also unusual.
- Is the user on the ML team that owns the hub account? Did they recently resign or receive notice?

### Step 5: Check approvals and related AI risk

```spl
| inputlookup ai_sanctioned_entities
| search allow_key="<user>|*" OR allow_key="<src>|*" OR allow_key="*|model registry" OR allow_key="*|local llm" OR allow_key="*|replicate"
| table entity_type entity provider scope expires owner reason enabled allow_key
```

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object="<risk_object>" source="* - HDSI AI * - Rule"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as sources min(_time) as first_seen max(_time) as last_seen by risk_object risk_object_type
| convert ctime(first_seen) ctime(last_seen)
```

- An expired approval explains a team that suddenly appears.
- `Threat - HDSI RBA AI Data Collection Kill Chain - Rule` treats this rule as the exfiltration step after a collection detection (file-access spike, clipboard to AI). `Endpoint - HDSI AI Usage Following Data Access Spike - Rule` before the publish is a strong combination.

### Step 6: Make a determination

- **True Positive:** proprietary weights, adapters or datasets published to an account the organisation does not control, or by a user with no publishing role.
- **Benign True Positive:** an approved ML team or CI job publishing to the organisation's own hub account, or publishing an approved open model.
- **False Positive:** a small `upload_file` of a non-model file through `preupload`, or SSE volume that was really inference traffic (see False Positive Scenarios).

---

## True Positive Indicators

- The target repository is under a personal or unknown hub namespace, not the organisation's.
- The local path points to internal checkpoints, fine-tuned adapters or training data.
- The source is ML infrastructure (`ml_infra=1`) and the user is not the team's publishing account.
- Upload volume in the hundreds of MB or more, outside normal working patterns.
- Preceded by a data-access spike, bulk copy to the host, or a new hub token on the command line.
- The user is leaving the organisation, or the same user shows other data-exposure detections.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| ML teams or CI jobs publishing open models to the organisation's hub account | Medium where such teams exist | Allow-list in `ai_sanctioned_entities` (user, host, `bunit` or organisation-wide; provider `model registry`, `local llm` or `replicate`), or add the CI runner to `..._process_filter` |
| `--push_to_hub` on a training script that later fails | Low | The flag counts when the job starts. Confirm the push in the hub audit log |
| Programmatic `upload_file` of a small non-model file (still calls `preupload`) | Low | It is a publish, but may not be a model. Check the file and repository |
| SSE app-name rows with no URL, or `huggingface-base` App-ID volume that includes inference | Low | Only volume above 100 MB/hour counts there. Hourly volume in validation never exceeded about 1 MB (App-ID) or 25 MB a week (SSE) |
| Kaggle data-science use | Low | Kaggle shares the `Model Registry` provider. Allow-list approved data-science users |

The rule cannot see which hub organisation a network-only upload went to, so a personal and a corporate account look the same there. Hugging Face, ModelScope and Kaggle share the provider name `Model Registry`, so one provider-scoped allow-list entry covers all three.

## Response Actions

### If confirmed True Positive

1. **Contain:** Ask the hub provider to take the repository down (Hugging Face, Kaggle and others have abuse and DMCA processes). Revoke the hub token used and block the user's access to the hub at the proxy.
2. **Preserve:** Capture the repository URL, commit history and file list before takedown, and preserve the host for forensics.
3. **Scope:** Identify which models, adapters or datasets left, their classification, and whether they contain customer or personal data.
4. **Notify:** Inform the model owner, legal and HR. Involve privacy if training data contained personal data.
5. **Remediate:** Restrict who can read model checkpoints, require hub publishing through an approved CI identity, and block personal hub accounts if policy allows.
6. **Document:** Record the evidence, the repository, the material exposed and the takedown status.

### If Benign True Positive

1. Add the publishing account, host or team to `ai_sanctioned_entities` with an expiry date:
   ```
   entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
   user,mlops_svc,Model Registry,provider,2027-06-30,ml-platform,publishes open models,1,mlops_svc|model registry
   system,gpu-node-01,*,global,2027-06-30,ml-platform,training cluster CI,1,gpu-node-01|*
   ```
2. Close the finding as Benign True Positive.

## Tuning Guidance

### Reducing false positives

- Allow-list legitimate publishers in `ai_sanctioned_entities`; do not widen the scope filters for this.
- Keep inbound logs out of the Web branch: `NOT sourcetype IN ("aws:elb:accesslogs","aws:waf")` in `..._filter`.
- Extend `..._ml_asset_regex` with your own CMDB category names so ML hosts get the +10 modifier.
- Set `..._untrusted_src` to `false()` only if your clients have public addresses.

### Adjusting thresholds

Measure your hourly upload shape to model hosts before lowering `_min_mb` (for example to catch LoRA adapters). Set it well above the observed `max_mb`, at least 5 × p99:

```spl
| tstats summariesonly=t allow_old_summaries=t sum(All_Traffic.bytes_out) as bytes_out from datamodel=Network_Traffic where `hdsi_ai_suspicious_model_file_exfiltration_traffic_scope` by All_Traffic.user All_Traffic.src All_Traffic.app _time span=1h
| eval mb=bytes_out/1048576
| stats count as entity_hours perc99(mb) as p99_mb max(mb) as max_mb by All_Traffic.app
```

Run the same against `Web` (`sum(Web.bytes_out)`, `..._web_scope`, `by Web.user Web.src Web.url_domain Web.site _time span=1h`) if a proxy or SSE logs bytes.

### Tuning macros

| Macro | Ships as | Purpose |
|---|---|---|
| `hdsi_ai_suspicious_model_file_exfiltration_filter` / `_traffic_filter` / `_process_filter` | `()` | Inline exclusions per branch |
| `..._web_scope` / `..._traffic_scope` / `..._process_scope` | model hosts and SSE names / hub App-IDs / broad command wildcards | What each branch reads |
| `..._upload_tool_regex` | publish-command regex | What counts as a publish command |
| `..._upload_url_regex` | upload-only API paths (no `commit`, no Spaces) | What counts as an upload-API request |
| `..._upload_app_regex` | `-upload$` | Upload App-IDs (firewall only) |
| `..._inference_regex` | HF router, inference API and proxy, OpenAI/Replicate-style inference paths | Dropped as inference |
| `..._min_mb` / `..._min_evidence_mb` | `100` / `10` | Volume thresholds |
| `..._ml_asset_regex` | word-bounded ML/GPU/data-science regex | +10 modifier |
| `..._untrusted_src` | public IPv4 or global-unicast IPv6 | `src` values that are never a risk object |
| `..._customizations` / `..._risk_score` | `search *` | Post-scoring hook / last-pipe score override (max 100) |

### Live validation (2026-10-09, 4 production ES tenants)

| Tenant | Model-host data | Parses (rule + 4 drilldowns) | Rows 4 h / 24 h / 7 d | Notes |
|---|---|---|---|---|
| A | PAN App-ID (`huggingface-base`, max ~1 MB per entity-hour); URL logs without bytes | OK | 0 / 0 / 0 | ~700 `git push` in 7 d, none with a URL; no publish commands |
| B | Proxy downloads only; inbound ELB/WAF with hub Host headers | OK | 0 / 0 / 0 | Inbound rows dropped; a global-IPv6 proxy `src` is classed untrusted |
| C | SSE (23 MB/week to the Kaggle app) and PAN App-ID (KB-scale) | OK | 0 / 0 / 0 | 9 `git push` in 7 d, none with a URL |
| D | None (inbound IIS only) | OK | 0 / 0 / 0 | No model-host data |

The widened process pre-filter matched 0 command lines in 7 days on every tenant. A synthetic end-to-end run on Tenant C produced the 13 expected detections (scores 35-50) and dropped all 8 negatives, including inference uploads, hub browsing, `--push_to_hub False`, `kaggle models create` and a look-alike hub hostname. v1.0 matched more than 500 unrelated assets with its "ML asset" regex on one tenant and its Web drilldown ran 4-5 minutes; both are fixed.
