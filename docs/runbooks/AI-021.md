# AI-021 - HDSI AI Browser Extension Activity

> **Detection ID:** AI-021
> **Package:** `hdsi_ai_browser_extension_activity` (v1.1.0, `deployment_type: global`, requires `hdsi_ai_rba_common`)
> **Search name:** `Network - HDSI AI Browser Extension Activity - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`, `action.risk = 1`); the HDSI RBA AI aggregators decide when accumulated risk becomes a notable.
> **Risk Objects / Score:** `src` (system) and `user` (only when the proxy attributes exactly one real user). Dynamic: base = highest tier score (capture 30, page_reader 20, writer 10, store_view or vendor_site 5) + 5 per extra product that reached a backend host, capped at 60; `risk_score = min(60, round(base x risk_multiplier))`, applied to both objects. Literal fallback 20 / 20.
> **MITRE ATT&CK:** T1176.001 (Software Extensions: Browser Extensions), T1588.007 (Obtain Capabilities: Artificial Intelligence)
> **Data Model:** `Network_Resolution` (DNS) OR `Web` (either is enough)
> **Schedule:** `7 * * * *` (hourly at :07)
> **Lookback Window:** `-65m@m` to `-5m@m`
> **Suppression:** 24 h (`86400s`) on `src,user`
> **Kill Chain Phase:** `collection` (`ai_kill_chain_phase`)
> **Last Updated:** 2026-10-09

---

## Overview

This detection finds endpoints using **extension-first AI assistants**: Monica, Sider, MaxAI, Merlin, HARPA, Bardeen, Tactiq, Wordtune and similar tools whose main product is a browser extension. These extensions read the page the user is viewing, or capture meeting audio and transcripts, and send that content to the vendor's own LLM backend instead of the organisation's sanctioned AI provider. That is page, document or meeting content leaving the organisation, often without the user thinking of it as an upload.

The rule matches DNS lookups and proxy requests to those vendors' backend hosts, and proxy-logged views of AI extension listings in the Chrome, Edge and Firefox extension stores. Several backend hosts also serve the vendor's own web, desktop or mobile app, so a hit proves the **product was used from that `src` (extension or web app)**, not that the extension is installed.

Extensions from mainstream providers (ChatGPT, Claude, Copilot, Gemini, Perplexity) share hosts with those providers' web apps and are covered by the AI web and DNS rules instead. Grammarly and QuillBot are deliberately not in the catalog (high volume, usually licensed).

## Detection Logic

### Plain English

1. **DNS leg:** `tstats` over `Network_Resolution` for the 20 backend domains in `..._domains(1)` (subdomains and trailing-dot names included), by `DNS.src` and `DNS.query`.
2. **Web leg (`append maxtime=240`):** `tstats` over `Web` for the same domains in `Web.url_domain` **or** `Web.site`, plus exact matches on the extension store hosts. `fillnull_value="-"` keeps rows with an empty `user` or `site`, and `ext_domain = coalesce(url_domain, site)`.
3. `..._catalog` maps each host to a product and a tier: `capture` (meeting capture or browser automation: Tactiq, HARPA AI, Bardeen), `page_reader` (sidebar assistants), `writer` (writing assistants), or `vendor_site` (only the bare or `www.` marketing host, weaker evidence).
4. A store URL counts only when `..._store_ai_regex` finds an AI term in the extension's detail-page slug (tier `store_view`, product "AI extension store listing"). This needs full URL paths (TLS inspection).
5. `unknown`, `-` and IP-shaped users and rows without a `src` are dropped. A single `bunit` is resolved (identity `bunit` for the user, else asset `bunit` for the `src`; placeholders and ambiguous multi-value matches are discarded and noted in `bunit_note`).
6. `ai_unsanctioned_filter(user,src,provider)` applies the allowlist per product (`provider` = `ext_product`).
7. **Aggregate per `src`.** `user` is set only when exactly one real user was seen.
8. **Score:** highest tier score, + 5 per extra backend product, capped at 60; x `risk_multiplier` (1.0 without a user), capped at 60.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `src` | Endpoint (system risk object) | `10.20.30.40` |
| `user` / `user_display` | Single proxy user, or the users seen, or "not attributed" | `not attributed` |
| `ext_product_list` | Products seen | `Sider, Monica` |
| `ext_tier_list` | Tiers seen | `page_reader, vendor_site` |
| `ext_domain_list` | Up to 10 hosts | `api2.sider.ai, api.monica.im` |
| `store_listings` | Store slugs of AI extensions viewed (store leg only) | `chatgpt-sidebar-...` |
| `evidence_list` | `dns`, `web`, `web_store` | `dns, web` |
| `event_count` | DNS lookups and proxy requests | `57` |
| `product_count` / `backend_product_count` | Products in total / products that reached a backend host | `2 / 2` |
| `bunit` / `bunit_note` | Business unit used for allowlisting, or why none was used | `ambiguous asset or identity bunit (3 values), not used for allowlisting` |
| `base_score`, `risk_multiplier`, `risk_score` | Scoring | `25, 1.0, 25` |

### Thresholds

There is no count threshold. One lookup of a catalogued backend host is enough evidence of use. The tier scores are the tuning surface.

| Parameter | Default Value | Macro | Notes |
|---|---|---|---|
| Tier scores | capture 30, page_reader 20, writer 10, store_view 5, vendor_site 5 | `hdsi_ai_browser_extension_activity_tier_scores` | Base risk per tier |
| Extra product bonus | +5 per extra backend product | in SPL | Vendor sites and store views do not count |
| Score cap | 60 (before and after the multiplier) | in SPL; override in `hdsi_ai_browser_extension_activity_risk_score` | Applies to `src` and `user` |

## Triage Steps

> **Estimated triage time:** 5-10 minutes. There is no notable for this rule. You reach it from an HDSI RBA AI aggregator notable (often `Threat - HDSI RBA AI Data Collection Kill Chain - Rule`) or a risk event.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Network - HDSI AI Browser Extension Activity - Rule" risk_object IN ("$src$","$user$")
| table _time, risk_object, risk_object_type, risk_score, risk_message
| sort - _time
```

- The risk message gives products, tiers, evidence and hosts. A score of 5 means a marketing-site visit or a store listing view only: low value on its own.

### Step 2: Review the DNS evidence

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime
    from datamodel=Network_Resolution
    where DNS.src="$src$" `hdsi_ai_browser_extension_activity_domains(DNS.query)`
    by DNS.src DNS.query
| rename DNS.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

- Backend API hosts (`api.monica.im`, `api2.sider.ai`, `chromium-extension.wordtune.com`) queried throughout the working day point to an extension in active use. Only `www.` or bare vendor hosts point to a website visit.
- A `src` that resolves many different products at high counts is probably a resolver or forwarder. Exclude it (see Tuning Guidance).

### Step 3: Review the proxy evidence and volume

Handles proxies that fill `url_domain`, `site`, or only one of them:

```spl
| tstats summariesonly=t allow_old_summaries=t fillnull_value="-" count sum(Web.bytes_out) as bytes_out sum(Web.bytes_in) as bytes_in values(Web.url) as url values(Web.http_user_agent) as http_user_agent min(_time) as firstTime max(_time) as lastTime
    from datamodel=Web
    where Web.src="$src$" (`hdsi_ai_browser_extension_activity_domains(Web.url_domain)` OR `hdsi_ai_browser_extension_activity_domains(Web.site)` OR Web.url_domain IN (`hdsi_ai_browser_extension_activity_store_domains`))
    by Web.user Web.src Web.url_domain Web.site
| rename Web.* as *
| eval url_domain=if(url_domain="-",site,url_domain)
| eval mb_out=round(bytes_out/1024/1024,2), mb_in=round(bytes_in/1024/1024,2)
| convert ctime(firstTime) ctime(lastTime)
| table firstTime, lastTime, user, src, url_domain, count, mb_out, mb_in, http_user_agent, url
| sort - count
```

- `mb_out` shows how much content was sent. Several MB in an hour points to document or bulk page capture; see AI-024 (incubating, not released).
- The proxy user identifies the person when DNS gives none.

### Step 4: Identify the host owner and user

```spl
| inputlookup asset_lookup_by_str where ip="$src$"
| table asset, ip, dns, nt_host, owner, bunit, category, priority
```

```spl
| inputlookup identity_lookup_expanded where identity="$user$"
| table identity, first, last, email, managedBy, bunit, category, priority
```

- In validation every DNS-only finding had no user. Use the asset owner, DHCP or the EDR's logged-on user to find the person.

### Step 5: Check for related AI risk on the same objects

```spl
| from datamodel:"Risk.All_Risk"
| search risk_object IN ("$src$","$user$") source="*HDSI AI*"
| stats sum(risk_score) as total_risk dc(source) as detections values(source) as rules count as events by risk_object, risk_object_type
| sort - total_risk
```

- This rule is the **collection** phase of `Threat - HDSI RBA AI Data Collection Kill Chain - Rule`: an upload or exfiltration detection for the same user within 4 hours after it raises a high-severity notable.
- It counts in the `local_tooling` vector of `Threat - HDSI RBA AI Multi-Vector Risk - Rule`.

### Step 6: Determine sanctioned status

```spl
| inputlookup ai_sanctioned_entities
| where tonumber(enabled)=1 AND (lower(entity)=lower("$src$") OR lower(entity)=lower("$user$") OR entity="*")
| table entity_type, entity, provider, scope, expires, owner, reason, allow_key
```

- Keys are `<user>|<product>`, `<src>|<product>`, `<bunit>|<product>` or `*|<product>`, all lowercase, where `<product>` is the lowercased `ext_product` (for example `brisk`, `tactiq`). A store listing view uses the product `ai extension store listing`.

### Step 7: Make a determination

- **True Positive:** an unapproved page-reader or capture assistant in use on a host that handles sensitive content.
- **Benign True Positive:** an approved product (for example Brisk for education, Tactiq or Bardeen for sales). Allowlist it.
- **False Positive:** a marketing-site visit only (score 5), or a resolver reported as the client. Accept the low score or exclude the resolver.

---

## True Positive Indicators

- Tier `capture` (meeting transcripts, browser automation) or `page_reader` backend hosts, queried repeatedly over the day.
- The user works with confidential data (HR, finance, legal, R&D, customer records) or attends sensitive meetings.
- Several extension products on the same `src` (`backend_product_count` above 1).
- Proxy `mb_out` to the backend is substantial, or an upload detection follows for the same user.
- The product is not on the organisation's approved list and the user has a sanctioned alternative.

---

## False Positive Scenarios

Evidence is from read-only live tests on 4 production ES tenants (Tenant A-D) on 2026-10-09.

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Marketing-site visit without installing anything (`www.getmerlin.in`): tier `vendor_site`, score 5. The most common low-value match | High | Accept the low score, or lower `vendor_site` in `..._tier_scores` |
| Vendor web app rather than the extension (`api.monica.im`, `api2.sider.ai`, `app.wordtune.com` serve both) | Medium | Same data risk; do not assume an installed extension. Confirm with endpoint or browser-management inventory |
| Approved education or sales tools (Brisk, Tactiq, Bardeen) | Medium | Allowlist with `<bunit>\|<product>`, `<src>\|<product>` or `*\|<product>` |
| Resolver or forwarder recorded as the DNS client | Low | Exclude it in `..._filter`, e.g. `NOT DNS.src IN ("192.0.2.53")` |
| Ambiguous asset business units (Tenant C: one IP mapped to `unknown` plus several sites), so `<bunit>\|<product>` keys do not apply | Medium on such tenants | Clean up overlapping asset records, or allowlist by `src` |

## Response Actions

### If confirmed True Positive

1. **Contain:** remove the extension from the browser (browser-management policy or EDR), and block the backend domains at the proxy or DNS security layer if the product is not approved.
2. **Notify:** inform the user and their manager; involve data governance when the user handles confidential data or meetings.
3. **Investigate:** find out what content the extension could read (pages, documents, meetings) during the period of use, and whether the vendor account is personal or corporate.
4. **Remediate:** enforce an extension allowlist through browser management, and point the user to the sanctioned AI assistant.
5. **Document:** record the findings in the case management system.

### If Benign True Positive

1. Add a row to `ai_sanctioned_entities` (common package) with `allow_key` `<bunit>|<product>`, `<src>|<product>` or `*|<product>` (all lowercase), an expiry date and the justification in `reason`.
2. To stop monitoring a product completely, remove its domain from both `..._domains(1)` and `..._catalog`.
3. If an aggregator notable was raised, close it as Benign True Positive and reference the approval.

## Tuning Guidance

### Reducing false positives

- Confirm that DNS `src` values are endpoints, not resolvers, and exclude resolvers in `..._filter`.
- Lower the `vendor_site` and `store_view` tier scores if marketing-site visits add too much background risk.
- If the extension population is large and approved, consider removing this rule from the Data Collection Kill Chain's collection list (`hdsi_rba_ai_data_collection_kill_chain_collection_detections`).
- To monitor Grammarly or QuillBot, add `grammarly.com`, `grammarly.io` and `quillbot.com` to both the domains macro and the catalog with tier `writer`, then allowlist the licensed population.

### Adjusting thresholds

Profile what the rule would emit, per source, over 7 days:

```spl
| tstats summariesonly=t allow_old_summaries=t count dc(DNS.query) as hosts from datamodel=Network_Resolution
    where `hdsi_ai_browser_extension_activity_domains(DNS.query)` earliest=-7d@d by DNS.src DNS.query
| rename DNS.* as *
| eval ext_domain=query
| `hdsi_ai_browser_extension_activity_catalog`
| stats sum(count) as lookups dc(ext_product) as products values(ext_product) as ext_products values(ext_tier) as tiers by src
| sort - lookups
```

### Key tuning macros

| Macro | Ships as | Use |
|---|---|---|
| `hdsi_ai_browser_extension_activity_filter` / `_web_filter` | `()` | Inline exclusions per leg (`DNS.*` / `Web.*` names) |
| `..._domains(1)` / `..._catalog` | 20 vendor domains / host-to-product-and-tier map | Keep the two in step |
| `..._store_domains` / `..._store_ai_regex` | Chrome, Edge, Firefox stores / AI-term regex | Store leg |
| `..._tier_scores` | 30/20/10/5/5 | Base risk per tier |
| `..._customizations` / `..._risk_score` | `search *` | Post-aggregation hook; last-pipe score override (max 100) |

### Adding allowlist entries

```
entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
group,education,Brisk,group,<YYYY-MM-DD>,<your_name>,<justification>,1,education|brisk
```

## Data Requirements

| Requirement | Details |
|---|---|
| Data Model | `Network_Resolution` (DNS dataset) and/or `Web`; either is enough |
| Required Fields | DNS: `DNS.src`, `DNS.query`. Web: `Web.src`, `Web.user`, `Web.url_domain` or a domain-style `Web.site`; `Web.url` (full path) for the store leg |
