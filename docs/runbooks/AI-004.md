# AI-004 - HDSI AI Unsanctioned CLI Execution

> **Detection ID:** AI-004
> **Package:** `hdsi_ai_unsanctioned_cli_execution` v1.1.0 (deployment type: global)
> **Search name:** `Endpoint - HDSI AI Unsanctioned CLI Execution - Rule`
> **Status:** Active. Risk-only (`action.notable = 0`). Notables come from the HDSI RBA AI aggregators.
> **Risk:** static. `user` 30 (when the account is a person) and `src` system 20. Service, machine and root accounts give system risk only.
> **MITRE ATT&CK:** T1588.007 - Obtain Capabilities: Artificial Intelligence; T1059 - Command and Scripting Interpreter
> **Data Model:** Endpoint.Processes
> **Schedule:** `4-59/15 * * * *` (every 15 minutes)
> **Lookback Window:** `-20m@m` to `-5m@m`
> **Suppression:** 24 h per `user` + `src`
> **AI kill-chain phase:** `execution` (multi-vector aggregator: `local_tooling`)
> **Last Updated:** 2026-10-09

---

## Overview

This rule detects endpoints running an AI coding or chat command-line tool: Claude Code, OpenAI Codex CLI, Gemini CLI, GitHub Copilot CLI, Amazon Q / Kiro CLI, Cursor CLI, Qwen Code, OpenCode, Amp, Aider, Shell GPT, tgpt, aichat, Charm mods, Fabric, Cline, the `llm` CLI and the `openai` CLI.

These tools send source code, files and terminal context straight to an external model provider, outside the browser, so web and CASB controls often do not see the content. Agentic CLIs (Claude Code, Codex, Gemini CLI) can also run shell commands and edit files as the logged-in user. An unsanctioned one is therefore both a shadow-AI data-handling finding and a possible execution channel.

The rule covers Windows, macOS and Linux:
- exact binary names, with any parent;
- generic names (`claude`, `llm`, `fabric`, `mods`, `cline`, `copilot`, `amp`), but only when launched from a shell or from a Claude Code install path;
- node, bun, deno, python, uv and pipx launchers whose command line names an AI CLI package path or bin symlink;
- the native Claude Code image path (`~/.local/share/claude/versions/<version>`).

Package installs and IDE-hosted Copilot runtimes are excluded.

## Detection Logic

### Plain English

1. **Pre-filter** (`hdsi_ai_unsanctioned_cli_execution_match`, inline in `tstats` on `Endpoint.Processes`). A process matches in one of four ways:
   - a distinctive CLI name (`_cli_names`), with any parent;
   - a generic name (`_generic_names`) whose parent is an exact shell or terminal (`_shell_parents`), or whose command line or image is a Claude Code install path (`_generic_path_patterns`);
   - a launcher (`_launchers`) whose command line contains an AI CLI package path or bin symlink (`_cmdline_patterns`);
   - a native Claude Code image path (`_native_path_patterns`).
2. **Drop non-use.** For launchers only, package-manager commands are dropped: `npm`/`pnpm`/`yarn`/`bun`/`pip`/`pipx`/`uv` install, update, list and similar, and `python -m pip|venv|pytest`. A process named after an AI CLI is never dropped, even when its prompt mentions `npm install`.
3. **Drop IDE-hosted Copilot** (`_ide_host_exclusion`): VS Code's Copilot agent host (`agent-host\sdk-cache`, `vscode-proxy`) and `copilot-language-server`.
4. **Classify** to a tool key from the first of these that applies:
   - the exact process name;
   - the native Claude Code path (only when the command line starts with it);
   - for launchers, an anchored package path, bin entry or `python -m <cli>` within the first four command-line tokens.

   Rows with no key are dropped.
5. Look the key up in `ai_tool_processes` (common package). Rows the lookup disables (`enabled=0`) or classifies as non-CLI are dropped. Set `provider`, `ai_tool` and `launch_context` (`terminal`, `ide_extension`, `interpreter` or `other`).
6. Null non-person users (`SYSTEM`, `root`, `NT AUTHORITY\*`, `LOCAL`/`NETWORK SERVICE`, `*$`, `unknown`). Drop rows with no host.
7. Remove sanctioned user, host, `bunit` group or organisation-wide entries with `ai_unsanctioned_filter(user,src,provider)`.
8. Aggregate per `user` + `src` and emit static risk: user 30, system 20.

### Key Fields

| Field | Description | Example Value |
|---|---|---|
| `user` / `user_display` | Account that ran the CLI (null for service and machine accounts) | `EXAMPLE\jdoe` |
| `src` | Endpoint (from `Processes.dest`) | `DEV-WS-42` |
| `ai_tool` | Classified CLI | `Claude Code` |
| `provider` | Provider used for allowlisting | `Anthropic` |
| `launch_context` | `terminal`, `ide_extension`, `interpreter` or `other` | `terminal` |
| `process_name` / `parent_process_name` | Process and parent names | `node` / `zsh` |
| `process` / `process_path` | Up to 3 command lines (300 characters each) and paths | `node /opt/homebrew/bin/gemini` |
| `count` / `firstTime` / `lastTime` | Process events in the window | `4` |

### Thresholds

None. Any execution of a catalogued AI CLI by a non-sanctioned user or host is reportable. Volume is bounded by the 24-hour suppression on `user,src`. Tuning is done through the name and path lists and the allowlist (see Tuning Guidance).

## Triage Steps

> **Estimated triage time:** 10 minutes. This rule raises no notable. You normally reach it from an HDSI RBA AI aggregator notable or from a user's or host's risk timeline.

Replace `<user>`, `<host>` and `<host_ip>` with values from the risk event.

### Step 1: Validate the risk event

```spl
| from datamodel:"Risk.All_Risk"
| search source="Endpoint - HDSI AI Unsanctioned CLI Execution - Rule" (risk_object="<user>" OR risk_object="<host>")
| table _time risk_object risk_object_type risk_score ai_tool provider launch_context risk_message
| sort - _time
```

- The message names the tool, the provider, the host, the user and the launch context.
- `ide_extension` means an IDE bundled the CLI, for example the OpenAI Codex IDE extension. `terminal` means a person typed it.

### Step 2: Identify the user and the host

```spl
| inputlookup identity_lookup_expanded
| search identity="<user>"
| table identity first last email managedBy bunit category priority watchlist
```

```spl
| inputlookup asset_lookup_by_str
| search nt_host="<host>" OR dns="<host>*"
| table nt_host dns ip owner bunit category priority
```

- Is the user a developer? Is the host a developer workstation, a build server or a production server? An agentic CLI on a production or jump host is far more serious than on a laptop.

### Step 3: Review the AI CLI process activity on the host

```spl
| tstats summariesonly=t allow_old_summaries=t count min(_time) as firstTime max(_time) as lastTime values(Processes.process) as process values(Processes.process_path) as process_path
    from datamodel=Endpoint.Processes
    where Processes.dest="<host>" `hdsi_ai_unsanctioned_cli_execution_match`
    by Processes.user Processes.dest Processes.process_name Processes.parent_process_name
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| table firstTime lastTime user dest process_name parent_process_name process_path process count
| sort - count
```

- Read the command lines. Look for flags that grant autonomy, such as `--dangerously-skip-permissions`, `--yolo`, `--full-auto` or `-p` with a long scripted prompt. Look for prompts that name sensitive data, and for pipes of files into the CLI.
- Check the first-seen time: a new install versus established use.

### Step 4: Review what the CLI started

```spl
| tstats summariesonly=t allow_old_summaries=t count values(Processes.process) as process values(Processes.parent_process) as parent_process
    from datamodel=Endpoint.Processes
    where Processes.dest="<host>" `hdsi_ai_unsanctioned_cli_execution_parent_match`
    by Processes.user Processes.parent_process_name Processes.process_name
| rename Processes.* as *
| sort - count
| head 100
```

- Agentic CLIs start shells, `git`, package managers, `curl` and test runners. Escalate when you see credential access, remote access, archive or upload tools, or changes to persistence locations.

### Step 5: Confirm network use of the provider

The DNS model is keyed by IP. Resolve the host's IP with Step 2 first.

```spl
| tstats summariesonly=t allow_old_summaries=t count from datamodel=Network_Resolution.DNS
    where DNS.src="<host_ip>" by DNS.query
| rename DNS.query as ai_domain
| eval ai_input_type="dns"
| `ai_domains_filter`
| stats sum(count) as queries values(ai_domain) as ai_domains by provider usage_type
| sort - queries
```

- `usage_type=api` or `ide` hosts (for example `api.anthropic.com`, `generativelanguage.googleapis.com`) confirm that the CLI talked to the provider.

### Step 6: Check related detections and sanctioned status

```spl
| from datamodel:"Risk.All_Risk"
| search (risk_object="*<bare user>*" OR risk_object="<host>") source="* - HDSI *"
| stats count as risk_events sum(risk_score) as total_risk values(source) as detections by risk_object risk_object_type
| sort - total_risk
```

```spl
| inputlookup ai_sanctioned_entities
| eval k=lower(allow_key)
| where like(k, lower("<user>|%")) OR like(k, lower("<host>|%")) OR like(k, lower("<bunit>|%")) OR like(k, "*|%")
| table entity_type entity provider scope expires owner reason enabled allow_key
```

### Step 7: Make a determination

- **True Positive:** an AI CLI that is not approved runs on a host or under an account that should not have it, or an approved tool runs in a context where it is not allowed (production host, privileged account).
- **Benign True Positive:** a developer evaluating or using an approved tool whose approval is not yet in `ai_sanctioned_entities`.
- **False Positive:** a classification error. Examples: a project script under a `bin` folder named exactly like a CLI, or a non-AI tool that shares a generic name and was launched from a shell.

---

## True Positive Indicators

- The user is not a developer, or the host is a server, jump host or production system.
- Autonomy flags, scripted prompts or file contents piped into the CLI.
- Child processes that touch credentials, remote access or data staging.
- Other local-tooling risk on the same host: MCP servers, agent frameworks, local LLMs, scripted CLI invocation.

---

## False Positive Scenarios

| Scenario | Likelihood | Mitigation |
|---|---|---|
| Developer evaluating or using an approved tool | High where developers adopt AI CLIs | Add `<user>\|<provider>`, `<bunit>\|<provider>` or `*\|<provider>` to `ai_sanctioned_entities` |
| VS Code Copilot agent mode starting a bundled `codex.exe` (the only `codex.exe` activity in 7 days on Tenant C) | Excluded by default | `_ide_host_exclusion`. Set it to `false()` only if Copilot agent mode is unsanctioned |
| Microsoft Service Fabric `Fabric.exe` (about 8,700 runs a day on 3 servers on one tenant) | Excluded by design | Generic names need an exact shell parent |
| Project script in a `bin` folder named exactly like a CLI (`node ~/proj/bin/claude.js`) | Low | Exclude the host or path in `..._filter` |
| A build host running a sanctioned CLI in CI | Medium | `<host>\|*` system entry, or `NOT Processes.dest IN ("build-*")` in `..._filter` |

## Response Actions

### If confirmed True Positive

1. **Contain:** stop the process and remove the CLI through EDR or IT. On servers, isolate the host if autonomous command execution was seen. Revoke any provider API keys found on the host.
2. **Notify:** the user's manager, the endpoint or platform owner, and the AI governance owner.
3. **Investigate:** use Steps 3-5 to find the working directory, the repositories involved, child processes and network use. Check whether secrets were in scope (`.env` files, cloud credentials).
4. **Remediate:** rotate exposed secrets, and remove the tool or move the user to the sanctioned tool. Add an application-control rule if policy requires it.
5. **Document:** record the tool, provider, host, user and evidence in the case.

### If Benign True Positive

1. Add the approval to `ai_sanctioned_entities` with an `expires` date. Use the provider string this rule emits: `Anthropic`, `OpenAI`, `Google Gemini`, `GitHub Copilot`, `Microsoft Copilot` (legacy `gh-copilot`), `Amazon`, `Kiro`, `Cursor`, `Alibaba Qwen`, `OpenCode`, `Sourcegraph`, `Aider`, `Shell GPT`, `LLM CLI`, `Charm`, `Fabric`, `Cline`, `tgpt` or `aichat`.
2. To stop detecting a tool everywhere, set `enabled=0` on its base-name row (for example `claude`, not `claude.exe`) in `ai_tool_processes`. One change covers every launch form.

## Tuning Guidance

### Reducing false positives

- Prefer allowlist entries with an expiry over macro edits.
- Exclude build or golden-image hosts in `hdsi_ai_unsanctioned_cli_execution_filter`, for example `NOT Processes.dest IN ("build-*")`.
- Use `hdsi_ai_unsanctioned_cli_execution_customizations` for post-aggregation filters, for example `search NOT provider="GitHub Copilot"`.
- To add a new CLI, add its distinctive name to `_cli_names`. A generic name goes in `_generic_names`, and its package path in `_cmdline_patterns`. Also add a row to `ai_tool_processes`.

### Adjusting thresholds

There is no numeric threshold. Before enabling, inventory current use over 7 days:

```spl
| tstats summariesonly=t allow_old_summaries=t count dc(Processes.dest) as hosts min(_time) as firstTime max(_time) as lastTime
    from datamodel=Endpoint.Processes
    where `hdsi_ai_unsanctioned_cli_execution_match`
    by Processes.user Processes.process_name Processes.parent_process_name
| rename Processes.* as *
| convert ctime(firstTime) ctime(lastTime)
| sort - count
```

The pre-filter is broader than the final classification, so this list is an upper bound.

### Adding allowlist entries

```
entity_type,entity,provider,scope,expires,owner,reason,enabled,allow_key
user,EXAMPLE\jdoe,Anthropic,provider,2027-03-31,secops,Claude Code pilot,1,example\jdoe|anthropic
system,build01,*,global,2027-03-31,platform,CI host runs approved AI CLIs,1,build01|*
group,engineering,Google Gemini,provider,2027-03-31,secops,Gemini CLI for engineering,1,engineering|google gemini
```

The user entity must be the `user` value exactly as the rule emits it. A group key only works for users who resolve in `identity_lookup_expanded` with a non-empty `bunit`. That was 17-20 % of interactive-process users on Tenants A and C.

| Tenant | Endpoint.Processes (24 h) | Parses (rule + 3 drilldowns) | Rows 4 h / 7 d | Notes |
|---|---|---|---|---|
| A | about 174M | OK | 0 / 0 | No AI CLI in 7 days. Service Fabric correctly gated out |
| B | about 51k (servers) | OK | 0 / 0 | Server-only telemetry |
| C | about 156M | OK | 0 / 0 | Only VS Code Copilot agent-host `codex.exe` (excluded by default). With the exclusion off, it is reported as `OpenAI Codex CLI` / `ide_extension` |

A synthetic positive control (38 rows, every OS form) gave identical results on all four tenants. It produced 23 expected detections and 15 expected drops. Expected volume today is 0 a day on all four tenants, because AI use there is browser and SaaS based.
